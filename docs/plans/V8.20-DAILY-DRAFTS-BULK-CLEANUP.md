## Maintenance lesson

Presentation extraction must keep sequential targets, per-draft history/memory,
partial-success behavior and functional edit updates in the page. Characterize
edits made during an awaited request and a target removed mid-batch; these are
more valuable than tests that only mirror JSX. Freeze transient progress only
in a disclosed visual fixture and test real expiry separately with a controlled
clock. Keep Clear confirmation in the existing handler and test accepted/declined/
failed outcomes fictionally. An empty live queue is a verification limit, not a
reason to seed records or delete customer drafts during a release smoke test.
