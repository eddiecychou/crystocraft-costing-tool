# Quote Detail Add Products release

Add Products prepares the full selection using the quote's agreed rates
and current supplier cost rates where required. It saves new lines and
the actual item count in one transaction and recognizes already saved
catalogue choices before retrying. Custom Item and Remove use the same
header transaction to coordinate their counts.

## Browser and emulator verification

- The designated QA admin (`QA_ADMIN_EMAIL`) signed in by email and
  password in fresh Chrome sessions on both origins. The dashboard,
  Range catalogue, Settings and Portal loaded. The catalogue survived
  refresh, and Quote Detail loaded without runtime or lazy-chunk errors.
- The designated approved buyer (`QA_CUSTOMER_EMAIL`) signed in separately
  on both origins. The shop, Range catalogue and one product detail loaded
  and survived refresh. The Portal and Quote Detail routes redirected to
  the shop. Staff controls and internal fields stayed private.
- On both hosts, a fictional quote kept an existing EUR 12.34 line and its
  agreed USD and EUR exchange rates of 8.25 and 9.45. The Corporate Gifts
  item saved at EUR 10.00, and two indexed Range variants sharing a SKU
  saved at EUR 8.73 and EUR 10.48. All four rows were reflected in the
  header count. Internal supplier cost used a separate Settings rate.
- A mixed selection with a missing agreed or supplier rate made zero
  writes. A rejected transaction also saved zero rows. The picker retained
  the selection, disabled repeat clicks while pending, and saved only the
  intended two lines when retried successfully.
- After a fictional lost confirmation, retry found the original plus the
  two saved lines and kept the count at three. It made zero further
  writes and kept all prices and rates. These hosted checks intercepted
  Firestore in the browser and exercised only fictional records.
- Nine real Firestore SDK cases passed in the loopback emulator before
  release, including two editors with overlapping selections, custom
  line changes, legacy keys, stale rates and the restricted staff role.
  The new suite is included in the required GitHub emulator job.

The transaction checks apply to the current editor. A tab still running an
older bundle uses its earlier save handler until it loads this build.
