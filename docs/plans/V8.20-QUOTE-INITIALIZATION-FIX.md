## Problem and scope

The quote header/items effect had no catch or pending state. A failed read left
an optimistic “Prefilled from the quote” banner; a delayed item response could
replace editable customer/UC/notes/lines. The common customer URL prefill could
also finish after the quote and replace its company name.

ShipmentForm now owns one initialization attempt for the route-keyed editor:
common customer/catalogue startup plus sequential quote header/items reads.
It applies quote header and lines together only after the attempt completes.
The existing mapper `quoteItemToOrderLine`, quote defaults, first-tier choice,
exact prices/quantities/units/images and Range validation remain unchanged.
Existing getDoc/getDocs cache/read semantics are retained; this does not introduce
a cross-document Firestore transaction or change quote versioning policy.

| State | Behavior |
|---|---|
| Loading | Visible quote-specific status; no editable form or Create/number controls. Back to quote and Order Listing stay available. |
| Error | Clear alert, Retry and Back to quote. No partial conversion form; missing/uploaded/invalid Range sources must be corrected before conversion. |
| Ready | Existing prefilled banner and editable defaults/lines. Create remains the existing validated/atomic order path. |
| Empty quote | Existing warning and manual Add line path retained; Create stays unavailable until a line exists, with ordinary validation unchanged. |

Retry reruns the complete initialization, clearing the previous error immediately.
Attempt cleanup discards abandoned successes/rejections, including customer reads
from a failed attempt. Route keys isolate quote Q/R, manual/direct contexts and
saved orders. Unrelated same-context query changes do not reset edited fields.
Create also checks quote readiness synchronously; UI state is not its only guard.

No quote/order/contact write occurs during initialization/Retry. No new backend,
API, schema, Firebase rule, permission, dependency or migration is required.
The SH-05B invoice recovery and existing Create-submit/navigation guards remain.
Conversion re-entry/backlink/multiple-order policy (SH-08) is a separate task;
this change neither imposes uniqueness nor repairs existing conversions.

## Verification

Twenty permanent new scenarios extend the actual ShipmentForm/Router fixture
in `qa/shipment-lifecycle.test.mjs`. All 41 lifecycle and 191 combined shipment
cases pass locally. External SDK reads are fictional/deferred; no credentials,
live writes, SO/SI/UC allocation or email is used. Coverage:

- Delayed header/items, both read failures and complete-source Retry.
- Common customer startup delay/failure and late URL-prefill ownership.
- Retry while a previous attempt still has reads pending, then preserve edits.
- Quote Q → R, saved-order/manual navigation and abandoned resolve/reject.
- Missing/uploaded sources, invalid Range quantity/price and successful retry.
- Empty-quote manual entry, exact first-tier prices/quantities/units/images and
  legacy UC/default fallbacks; edits survive unrelated query changes.
- Existing optional catalogue read failure retains its empty-catalogue fallback.

The fixture uses bounded per-case deadlines and boolean DOM assertions. A wrong
initial expectation for the optional catalogue fallback made Node inspect a huge
React DOM object while formatting a failure; that harness assertion is corrected
without changing the app's existing fallback. Never compare an unexpectedly
present React DOM tree to null when a boolean assertion gives a focused failure.

The new tests already run through test:shipment-display, prebuild and the required
product-search job. Both GitHub jobs remain mandatory on the exact release SHA,
followed by fresh candidate and production admin/approved-customer gates. Local
visual/browser evidence and CI/release identities will be appended after checking.
