# Freight Comparison choice and cargo ownership

Freight Comparison stores a single decision per order in
`freight_decisions/{orderId}`. Choose and Unmark use a transaction and
update only the decision. Unmark applies only if that quote is still the
current choice. Deleting the chosen quote clears the choice in the same
transaction. The UI waits for acknowledgement before showing a new choice.
If confirmation fails, it keeps the last known choice and offers Reload
comparison.

The Firestore rules keep decision reads and writes within the existing
Shipping permission. They check that the order exists, that any chosen
quote belongs to it, and that a chosen quote is cleared or replaced before
deletion. Existing freight quotes retain their saved prices, exchange-rate
comparisons and cargo. A single legacy choice remains visible until an
explicit decision is saved. Multiple legacy flags prompt the operator to
choose. Existing sessions must reload after release so their controls use
the decision instead of the old quote flags.

Adding a quote starts from the selected scenario's saved totals. Changing
scenario or choosing no scenario resets all cargo inputs, including manual
overrides from the previous scenario. Missing fields stay blank. A fresh
transaction checks that the scenario still belongs to the order and that its
totals match the form's source. If they changed, Reload packing totals
refreshes cargo while retaining the vendor, quoted price and notes.

The form reuses its quote ID when retried after an uncertain response. An
acknowledged add appears immediately without a list refresh. Startup reads
show Retry on failure. No historical decision or cargo backfill is required.
