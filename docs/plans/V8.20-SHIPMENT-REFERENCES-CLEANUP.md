## Scope and ownership

ShipmentDocumentReferences.jsx owns only the existing Document References card:
SO, UC, customer PO, invoice number, revision and source-PI link. It receives
controlled values, the original field-change/allocate callbacks, busy/error
states, invoiceFieldRef and a parent-owned revision callback. No extra DOM
wrapper, state, effect, memoization, read, allocation, validation or write.

ShipmentForm retains doAllocateSo, doAllocateUc, doAllocateSi, all allocation
state/errors and immediate saved-order persistence. The SI/UC allocator is still
one existing service call; the card does not implement counters or a second
allocation path. Best-effort WooCommerce registry updates and existing warning
semantics remain. The original functional revision update remains inline in
the parent; the child calls it. Passing invoiceFieldRef as an ordinary named
prop keeps it on the same input, so the parent's invoice=1 effect still scrolls
and focuses after loading. No child focus effect or ref wrapper is introduced.

Schedule & Terms, import/adoption, line state/identity, header loading/reset,
validation, totals/precision, deposits/discounts, allocations, save/delete,
stock transactions and all print/Excel templates remain unchanged. Existing
source-file URL/name fallback, target and rel attributes are preserved.

## Existing accounting gap found during characterization

total/deposit and the manual HKD-payout fallback despite source values. The page
header load omits total_amount; shipping.normOrder omits woo_net_payout_hkd.

and warnings to prevent silently mixing an accounting change into presentation
cleanup. TECH-DEBT records a separate fix/audit candidate. No live order/registry
audit or correction was performed; affected real records/counts are unknown.
