## Scope and ownership

`shipping.orderEditFields(order, blankDestination)` owns the existing saved-order
to editable-header whitelist. ShipmentForm supplies its existing destination
blanks and applies the returned object only after its guarded order/line reads.
The mapping preserves every original expression and fallback, including contact,
legacy UC, imported PI reference totals, accounting/discount/deposit values,
revision/hide-quantity treatment and WooCommerce totals/fees/HKD payout metadata.
It does not parse or round stored amounts, recalculate totals, copy unknown order
fields into editable header state, or mutate the record/defaults.

The editor remains the owner of record identity, requests, complete header/line
pair loading, source files, Retry, form state, allocation, atomic saves, pending/
error feedback, financial-index sequencing and navigation. The recent lifecycle
repair remains intact. Existing order creation, stock, financial exports, rules,
authentication policy and server functions are unchanged by this extraction.
The form is 44 lines shorter (1006 → 962); this moves one responsibility rather
than reducing the total codebase by that amount.

The editable-header shape deliberately differs from `normOrder` storage defaults.
Keep blank/null/zero distinctions and legacy behavior; do not replace this
mapping with storage normalization or a raw order spread.
