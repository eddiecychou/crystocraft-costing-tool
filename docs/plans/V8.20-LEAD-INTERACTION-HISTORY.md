# V8.20 — lead interaction history

only after both required GitHub jobs pass. No email sending or business-record

## Cause and correction

The live enquiries.date single-field override contains only COLLECTION_GROUP
ascending/descending indexes. listInteractions reads one parent's enquiries
collection with orderBy('date', 'desc'), which needs COLLECTION descending.
The override replaces the normal collection indexes, so that query fails even
though the history records still exist. The old viewer has no rejection handler
and its finally clears loading, misleadingly presenting an empty history.

Restore COLLECTION ascending/descending in firestore.indexes.json while keeping
both group indexes. The pinned, dry-run-first
scripts/repair-enquiries-date-index.mjs merges those additions with the current
live field configuration. --apply enforces exact-SHA release CI, then patches
only enquiries.date with updateMask=indexConfig, waits for completion and
requires all four indexes READY. It never reconciles unrelated composite indexes,
touches TTL, rules or data, or changes query paths/order. Baseline, plan, operation
and final configuration are saved under ignored qa/out/lead-history-release.
This uses the official [single-field configuration API](https://docs.cloud.google.com/firestore/docs/reference/rest/v1/projects.databases.collectionGroups.fields/patch).

The viewer now distinguishes a failed request from empty history, offers Retry,
and ignores late results/errors after a contact change or unmount. Add/delete
targets and payloads remain unchanged. A successful save followed by a failed
read is reported as a history-loading problem, avoiding a misleading save error
and a repeated write.
