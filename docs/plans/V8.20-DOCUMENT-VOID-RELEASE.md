- The designated QA admin signed in by password in a clean Chrome context on each origin. The dashboard, Settings, Portal and Range loaded, including after refresh. A real read-only Finance lookup for an unused fictional SI returned 404 from the new endpoint.
- The approved buyer signed in by password in a separate fresh context on each origin. The Range catalogue and a product detail loaded through refresh. Portal and the PI route redirected into the customer shop. Staff controls, costing and internal notes were absent. The production Finance endpoint also refused the approved buyer's direct lookup. Both sessions passed the auth and runtime checks.
- Hosted browser fixtures exercised the required reason, PI audit readback after reopening, availability of the next PI revision and suppression of print and Excel for a voided SI. The same fixtures voided a split SI and a reissued SI, preserving the first SI and their shared UC. A simulated lost response kept the entered reason and its retry produced one audit entry.

Loopback Firestore and PostgreSQL fixtures separately exercised the real transactions, protected audit records, stale saves and the late financial follow-up guard. The portal test verified that a mirrored JES row could not restore access to the voided SI.
