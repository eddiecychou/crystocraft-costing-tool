# Portal badge: action needed versus waiting for reply

Requested during the concurrent-edit release on 9 November 2026. The menu badge and Portal review banner should count pending applications that need the operator's attention. A confirmed follow-up with state **Waiting for reply** no longer contributes. Pending approval remains unchanged; all applicants remain discoverable in the Pending tab. Marking information received makes that pending applicant actionable again. Saved drafts and unknown/sending outcomes remain actionable. This follows OC's recorded follow-up state, without inferring an external email's delivery.

Private correspondence remains server-only. An admin-authenticated, read-only `list_account_followup_states` action in the existing portal-invite API returns only UID and a waiting boolean for up to 100 IDs. It never exposes drafts/messages or updates users, sends mail, approves accounts or enrols marketing contacts. Existing historical follow-ups work immediately, with no migration. Direct Firestore reads and writes of the private correspondence remain denied even to browser admins.

The shared count retains its live pending-user subscription, resolves private states in bounded batches, refreshes after follow-up actions and checks periodically/on return for other sessions' changes. Responses from an older pending snapshot are ignored. If private state is temporarily unavailable, the Pending count remains conservatively visible with an unavailable notice. Non-admins neither subscribe to the queue nor request private status. Desktop and mobile menus use the same count.

Verification uses fictional applicants, actual UI, real Firestore rules and intercepted mail. It covers waiting/draft/unknown/received states, account retention in Pending, refresh after send/received, late responses, large queues, input validation, unauthorized callers and absence of record or email changes from status reads. The local production build passes all 1,144 prebuild tests, with 18 portal UI cases. All 24 actual backend/rules cases pass with intercepted delivery. Release evidence pending both exact-SHA jobs and fresh candidate/production role checks.
