## Confidentiality and compatibility plan (before migration)

1. Customer profile creation uses a small legacy signup allowlist. Self-updates permit only contact/currency preferences and login stamps, never identity, approval, invitation or pricing metadata. Legacy approval derives linkage from the saved CRM company on the server. ERP history independently derives its code from that company on every request, never the mirrored profile code.
2. Keep original product documents, internal remarks, images and supplier quotes intact. Deny customers direct access to corporate product roots, image documents and pricing documents. A token-authenticated catalogue API returns an explicit customer field projection, approved selling tiers and only eligible images. Server-side branding uses the linked customer's current sensitive flag. Customer detail, shop, customizer, featured cards and proposals use that projection; admin tools retain internal access. No product/quote duplication or image-byte changes. The customer projection refreshes on navigation, tab focus and every 60 seconds while visible, replacing raw Firestore listeners.
3. Existing published markup stays in the now-internal customer_prices record. A separate bounded migration moves user corp_markup_override/pricing_group fields to account_pricing/{uid}, atomically removing those copies from the self-readable profile. It preserves exact field values, records the previous values in that internal record, refuses conflicting destination values, supports dry run and is idempotent. Admin edit, invite approval and price publishing use the internal record. No sale-price recalculation.
4. ProductForm saves only changed form-owned fields in a transaction. A conflicting edit stays on screen with the user's draft; unrelated concurrent gallery/publication changes survive.
5. Contact review includes metadata from explicitly linked marketing contacts, deduplicates link IDs and marks missing linked records partial. It never guesses linkage or sends outreach.
