# Exchange-rate loading review and proposed fix

26 November 2026, Australia/Sydney. Reviewed committed OC source
`befc7b7a`. Fictional cases ran the real Pricing Tiers, Range Costing,
new Quote and Quote Detail screens in headless Chrome. The test
allowed only loopback requests and used in-memory Firestore fixtures.
The quote check captured the saved data passed to the export component.
[Fixture and results](#verification)

## Findings

### 1. Corporate Gifts can publish using defaults before Settings loads

The pricing page starts with RMB 1.09, USD 7.78 and EUR 8.60. The product
and tier data can finish loading while the rate request is pending.
The Publish button checks costs against the current rate map, which
already contains those defaults.

One fictional component cost USD 100, with a 2× markup. Clicking
**Publish prices** before the Settings response saved HKD 1,556 to the
customer's tier, representative tier and parent pricing summary. Releasing
the response with USD 8.00 marked the page out of date. The three saved
values remained HKD 1,556. With the Settings response available before
the click, the same fixture published HKD 1,600.

A missing Settings document, missing USD field, text value and rejected
read also left the default available for publishing. A stored numeric
zero or negative USD rate blocked publishing because the conversion
helper rejected it. The rejected read produced an unhandled browser
error. [Rate loading](../../src/pages/PricingTiers.jsx#L19) ·
[Publish writes](../../src/pages/PricingTiers.jsx#L135) ·
[Cost conversion](../../src/costCurrency.js#L11)

### 2. A late Settings response can replace a rate entered on a new quote

The form starts with its own copy of the defaults. When Settings
returns, any non-null RMB, USD or EUR value replaces the current input.
Entering USD 7.95 while Settings was pending then releasing the response
at USD 8.00 resulted in **8.00** being saved. Clicking Create Quote before
the delayed response saved the initial USD 7.78.

Missing Settings used USD 7.78. A USD field of `"8"` saved as numeric 8.
With a nonnumeric string the input appeared blank, and the captured
write contained `NaN`. Zero, negative eight and a manually cleared
USD field also reached the write as 0, −8 and 0 respectively. A rejected
request left the default available and produced an unhandled browser
error. The four-decimal configured RMB value 1.1686 saved exactly in
Chrome. [Load and default logic](../../src/pages/QuoteForm.jsx#L10) ·
[Quote creation](../../src/pages/QuoteForm.jsx#L120) ·
[Input controls](../../src/pages/QuoteForm.jsx#L246)

### 3. Range already waits and keeps draft saving available

The Range page disabled **Save & publish** during loading and for a
missing document, omitted USD, nonnumeric text, numeric string, zero,
negative USD or a rejected read. **Save costing** succeeded in every
case. Releasing a delayed valid response restored the publish action
and the test published internal costing successfully. The error path
displayed a retry instruction. The existing Range pricing hold remains
an independent publication check. [Rate loading](../../src/pages/RangeCosting.jsx#L236) ·
[Publish guard](../../src/pages/RangeCosting.jsx#L329) ·
[Draft and publish paths](../../src/pages/RangeCosting.jsx#L367)

### 4. Existing quotes already carry their own saved rates

A fictional sent HKD quote carried a USD rate of 8.25 and a saved
HKD 82.50 line. With Settings configured at USD 9.10, reopening the
quote and opening export still passed its original header and line
snapshot. Adding a USD 10 Range SKU used the stored 8.25 and created
another HKD 82.50 line. Duplicating copied all three saved rates into
the new draft. The harness observed zero Settings reads for those
actions and no change to the original rate fields.

Corporate Gifts line insertion in Quote Detail has a different read
of current Settings for its **internal supplier cost snapshot**. Its
selling-price conversion uses the quote's saved rates. Source review
also found different fallback expressions for legacy quotes with
absent rates. Those are distinct decision points when discussing
historical records. [Quote reopen](../../src/pages/QuoteDetail.jsx#L132) ·
[Quote line conversion](../../src/pages/QuoteDetail.jsx#L274) ·
[Export input](../../src/pages/QuoteDetail.jsx#L637) ·
[Duplicate header](../../src/quoteConversionModel.js#L67)

## Proposed fix

1. **Share Settings loading and validation.** Reuse
   `settings/exchange_rates` and the current HKD-per-currency convention.
   Expose loading, available, missing and read-error states. Keep
   configured rates separate from one source of suggested defaults.
   Accept finite positive numbers as configured rates, keep HKD at 1,
   and report the relevant missing or invalid currency. Preserve
   the existing RMB/CNY conversion convention.
2. **Gate Corporate Gifts publication.** Present a clear loading or
   retry state, and evaluate the rates required by the selected tiers
   and tooling before the first write. Use the same validated rates
   for the customer, tier and summary writes. The fixture should
   produce zero writes while a required rate is pending or unavailable,
   and HKD 1,600 once USD 8.00 loads. Previously published rows remain
   readable during a failed or incomplete read. Cover HKD-only costs
   and missing unused currencies explicitly so the guard is scoped to
   the inputs publication needs.
3. **Protect new quote input and the saved snapshot.** Apply valid
   configured rates only to untouched fields. While the normal lookup
   is pending, show that state before creation. On missing or failed
   reads, show which inputs need review and allow staff to confirm or
   replace visible suggested values. Validate a finite positive rate
   for every rate field being saved. Preserve decimal precision and
   record the final values in the existing quote header fields.
4. **Carry forward the existing quote and Range contracts.** Read
   agreed rates and saved lines from the quote on reopen, export and
   duplication. Copy saved values as stored, including valid historical
   numeric strings. Keep the saved selling prices separate from
   supplier-cost conversion on newly added lines. Preserve Range draft
   saving, the missing-rate publish guard and B0016 protection. Any
   change to how older quotes with missing snapshots are handled would
   need its own examples and approval.

Start with the Corporate Gifts publish gate, then add the new quote
input and validation fix. Check both against the same fictional
Settings cases. Reopen a saved quote under different Settings and
compare its stored rates, line values and duplicate before release.
The review scope is OC costing and quotations. Finance uses its own
accounting rate workflow.

## Corporate Gifts publish guard

The Pricing page reads `settings/exchange_rates` from the server. A
required rate must be a finite positive number. HKD converts at 1, and
CNY tooling uses the RMB rate. The page shows why publishing is paused
and offers a retry after a missing, invalid or failed Settings read.
The Publish action checks the same condition before reading buyers or
writing prices. An explicit publish uses one calculated cost per tier
for buyer prices, representative tier prices and the product summary.
The published-price status compares only the rates used to calculate
the price, including when reading an older publish signature.

Eleven automated editor tests cover delayed, missing, invalid and failed
reads, retry, tooling and volume tiers, and HKD-only prices. Eight Chrome
scenarios with fictional Corporate Gifts records verified zero writes
while blocked. With USD 8.00, an explicit publish wrote HKD 1,600 to
each expected location. A separate Chrome check reopened and duplicated
a fictional sent quote with a saved USD rate of 8.25 while Settings
showed 9.10. The quote and duplicate retained the agreed rates, and the
existing line remained HKD 82.50.
