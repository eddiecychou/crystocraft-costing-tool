## Owner clarification

Exploration usually means ongoing back-and-forth about products, ideas,
requirements or samples before a quotation or PI is issued for that project.
Many recently contacted customers may fit, but the owner explicitly selected
**manual Exploration**, since recurring customers can have several projects.
An open task, a recent conversation, outreach or an AI summary does not assign it.

Use Set work stages → Exploration → Save stages. Clear Exploration when that
particular discussion moves into quotation/order. Keep it selected if another
project remains exploratory. Existing open quotation and order badges can coexist
with manual Exploration for other work; historical fulfilled orders do not stop
new exploratory work.

## UI changes and ownership

- Purple Exploration, amber Quotation, green Order & Production. Reuse the
  existing badge-concept / badge-sampled / badge-active status variants in
  src/index.css; no palette or shared CSS change. These are the deliberate
  semantic-status colours allowed by DESIGN-SYSTEM.md §1.1.
- WorkStageBadge.jsx owns stage badge presentation for both dashboard rows and
  the customer dialog. Labels and descriptions share dashboardWorkbench.js.
- Work stages is visible directly below the customer's tasks, before the
  collapsed email summary. Setting a stage no longer requires opening Current
  work and linked records. Remove the redundant stage-text suffix on that
  accordion; coloured badges already show the stages above it.
- The editor explains the three stages and multiple-project use. Checkbox names
  stay Exploration / Quotation / Order & Production; descriptions are associated
  with aria-describedby. Stage choices, Save and Cancel have 44px touch targets.
