# Shipping invoice identity

UC Registry links for app invoices now carry the selected sales invoice number. The staff print route checks that number against a server-confirmed order and line snapshot. Older or missing invoices show a message directing staff to the original issued document or Finance. The page offers print and Excel only when the selected invoice matches. Existing order-only links continue to open the current document. Legacy imports that stored the invoice number in the SO field use that invoice number on the staff print page, PDF title and Excel number and filename.

Fictional split and reissue tests clicked both Registry entries for one order and checked the two destinations, the historical message, the current printed number and the actual workbook. An in-flight reissue, missing order and blank selection also failed closed. A Chrome-rendered legacy PDF and its Excel export both showed `SI260071`. The repository's invoice recovery suites ran in GitHub CI. This was an app-only release with no invoice, order, registry, rules or migration writes.
