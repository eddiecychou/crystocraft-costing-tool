## Authenticated verification

- The designated QA admin (`QA_ADMIN_EMAIL`) used the real email/password login
  in a clean Chrome context. Dashboard, Range catalogue, Settings and Portal
  navigation were available. The catalogue loaded again after refresh.
- The approved QA buyer (`QA_CUSTOMER_EMAIL`) signed in independently via the
  real login form in a fresh Chrome context. Shop, Range and product detail
  loaded. Product detail survived refresh, internal fields were absent and the
  admin Portal route redirected the buyer to the shop.

Both roles passed the runtime checks on candidate and production. The first
candidate returned HTTP 502 on the buyer catalogue because a symlinked
`node_modules` caused the manual upload to omit Firebase Admin from function
packaging. It remained a draft. The corrected candidate used a physical
`npm ci` install in the isolated release checkout. Its catalogue returned
HTTP 200 after sign-in, with the same source SHA and frozen front-end artifact.

note, purchase order and invoice reads to the served print pages. The issuer
