## Implementation

- Code changes clear the previous link, then link only a unique exact new code.
  Default library descriptions follow the new colour; custom text is preserved.
  Received PO stock identities cannot be changed by the editor without reviewing
  the receipt. Its save guard reads current receipt state transactionally.
- Receipt matching rejects stale/deleted links and ambiguous code-only matches;
  corporate component IDs cannot accidentally select a range stock item.
- Receipt rows retain their source PO indices, group repeated stock targets and
  sum quantities before assigning class/SKU/generation movement IDs. A single
  Firestore transaction owns all movements, cached balances and received state.
  Stale previews and unfinished legacy postings are refused; retries/concurrent
  matching requests cannot double-post. Shared stock staging preserves opening
  stock, reservations and monotonic sequences.
- Review receipt reads actual movements. Its full-legacy-receipt correction only
  adds provably missing quantities. It refuses partial, ambiguous, changed,
  unknown and over-received states; checks source lines, commercial values,
  movement contents, stock snapshots and generation again inside the transaction.
  Old movements remain append-only. The original red item/movement is untouched
  when its delta is zero. Corrected links, default descriptions, received rows,
  missing movements/balances and the before/after audit commit atomically.
  Replays return the already-corrected receipt without posting or rewriting it.
- Reversal uses actual recorded movement quantities, not misleading legacy row
  totals, and refuses a stale generation or unfinished previous reversal.
- The detail screen listens for PO changes. Receipt keys include source rows;
  the new review/confirmation UI has Simplified Chinese labels and uses an
  on-page confirmation rather than a native browser popup.
