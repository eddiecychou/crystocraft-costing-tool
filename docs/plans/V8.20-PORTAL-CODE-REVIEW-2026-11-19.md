# Customer portal code review

19 November 2026 · Local source at `5f7a77af` · Scope includes sign-up and approval, catalogue and media access, enquiry drafts, and customer invoice history and exports.

## Closed on 20 November 2026

All 11 findings were fixed and verified in production. The checklist follows the order of the original findings below.

### P1 · Access, privacy and invoice accuracy

- [x] **Range visibility and pricing.** Buyers see published designs and their selling prices. Costing and markup stay internal. [Range visibility release · `70876f2e`](V8.20-RANGE-PORTAL-VISIBILITY-RELEASE.md)
- [x] **Invoice history privacy.** OC and JES check company ownership and issuance before returning buyer-facing invoice fields. [Issued invoice history release · `757d3a2d`](V8.20-PORTAL-ISSUED-INVOICE-HISTORY-RELEASE.md)
- [x] **Brand Gallery access.** Buyer previews and downloads require current approval and company access. The migration revoked all 59 legacy file links. [Brand Gallery release and migration · `a8338c0d`](V8.20-BRAND-GALLERY-ACCESS.md)
- [x] **Google identity.** Google applications and invitation claims require a verified email and a Google sign-in. [Google identity release · `5f06f011`](V8.20-PORTAL-GOOGLE-IDENTITY-RELEASE.md)
- [x] **Enquiry draft privacy.** Each buyer sees only their own saved selections and notes when returning to a shared browser. [Enquiry draft privacy release · `c48ef742`](V8.20-ENQUIRY-DRAFT-PRIVACY-RELEASE.md)
- [x] **Split and reissued invoice links.** OC links identify the exact invoice. An earlier invoice without a verified copy shows “Original unavailable”. [Issued invoice history release · `757d3a2d`](V8.20-PORTAL-ISSUED-INVOICE-HISTORY-RELEASE.md)
- [x] **Legacy JES export totals.** PDF and Excel use the issued header total. Both exports showed USD 90 for the fictional invoice with USD 100 in lines. [Issued invoice export verification · `757d3a2d`](V8.20-PORTAL-ISSUED-INVOICE-HISTORY-RELEASE.md)

### P2 · Recovery and everyday use

- [x] **Interrupted sign-up.** Retrying in the same browser completes the original application with one account and one staff alert. [Sign-up retry release · `ee7568a2`](V8.20-PORTAL-SIGNUP-RETRY-RELEASE.md)
- [x] **Concurrent approvals.** Account, pricing and invitation status commit together. A second reviewer sees the conflict and retains their unsaved edits. [Portal approval release · `7f1cc548`](V8.20-PORTAL-APPROVAL-RELEASE.md)
- [x] **Invoice source outages.** Buyers can retry OC or JES independently while invoices from the other source stay visible. The empty-history message requires both sources to succeed. [Invoice history retry release · `c722b0d5`](V8.20-PORTAL-INVOICE-SOURCE-RETRY-RELEASE.md)
- [x] **Enquiry quantities.** Stock stays in pieces, made-to-order quantities use whole cartons, and submission rechecks available stock. [My Enquiry quantities release · `5d8f216d`](V8.20-MY-ENQUIRY-QUANTITIES-RELEASE.md)

Both Google actions accept these as Google identity, and the resulting Google profile takes a different approval and notification path. [Identity helper](../../netlify/functions/portal-invite.js#L123) · [Google actions](../../netlify/functions/portal-invite.js#L1140) | Check the verified email and Google sign-in provider on these two actions before recording the application or claim. | P1 | **An enquiry draft carries over to the next customer on a shared browser.** Every account reads and writes the same local storage key. The next buyer can see saved item notes and submit the previous buyer’s choices under their own company. [Cart storage](../../src/customer/store.jsx#L53) · [Submission](../../src/customer/EnquiryPage.jsx#L72) | Scope the persisted draft and mounted cart to the authenticated UID. Keep same-account drafts across visits and avoid assigning an existing ownerless draft to the next login. |
| P1 | **An old OC invoice link can open a replacement invoice.** The URL stores the order ID alone. On reopening, the print page checks and renders the SI currently on that order. A fictional reissue gave SI990001 and SI990002 the identical link. [History link identity](../../src/domain/salesInvoiceHistory.js#L38) · [Print read](../../src/customer/CustomerInvoicePrint.jsx#L55) | Pin new links to the exact issued invoice and verify the identity on open and export. | P1 | **Legacy JES invoice exports can show the wrong total.** The detail response includes the invoice header amount, but the print view drops it and uses the line sum for both print and Excel. [Header mapping](../../src/customer/CustomerInvoicePrint.jsx#L73) · [Totals and Excel](../../src/customer/CustomerInvoicePrint.jsx#L106) | Keep the issued amount as the total and the line sum as the subtotal. Show a documented adjustment where available. Handle a missing header amount explicitly. |

## Recovery and everyday use

| Priority | Finding | Recommended change |
| --- | --- | --- |
| P2 | **A failed sign-up can lock out its own retry.** Email registration creates the Auth user before saving the application, profile and alert. If that save fails, a retry with the same email sees the orphaned Auth user and returns “already registered.” [Retry check](../../netlify/functions/portal-invite.js#L399) · [Account creation](../../netlify/functions/portal-invite.js#L419) | Make partial registration recoverable for the same verified applicant. Retry the missing application and alert once and preserve existing accounts. |
| P2 | **Approval and the invitation status can disagree.** Approval commits the user and pricing, then updates the invitation separately. A failure between these writes leaves an approved buyer in the claimed queue. Concurrent staff decisions can also overwrite a newer invitation state. [Approval writes](../../netlify/functions/portal-invite.js#L1051) · [Rejection](../../netlify/functions/portal-invite.js#L646) | Check the current invitation state and apply the decision, profile and pricing atomically. Handle email delivery separately so a mail retry cannot repeat an approval. |
| P2 | **An invoice source outage can look like an empty history.** The OC list converts a failed read into an empty array. The JES client turns an unsuccessful HTTP response into zero rows. If both lists are empty, the buyer sees “No invoices on file yet.” [OC read](../../src/customer/OrderHistoryPage.jsx#L59) · [JES client](../../src/customerOrderHistoryApi.js#L17) | Keep successful rows visible, distinguish unavailable sources and offer Retry. Reserve the empty state for successful reads. |
| P2 | **My Enquiry changes piece orders into carton quantities.** Range detail accepts loose pieces from stock, but the cart always switches to carton controls when a pack size exists. For five pieces with a 24-piece carton, it displays one carton alongside five pieces. Pressing plus changes the quantity to 48 without rechecking the stock limit. [Detail cart line](../../src/customer/FigurineDetail.jsx#L201) · [Cart quantity controls](../../src/customer/EnquiryPage.jsx#L150) | Persist the buyer’s stock or made-to-order choice. Edit stock lines in pieces, carton lines in cartons, and recheck applicable stock limits when quantities change. |
