# Flexible marketing catalogue layouts — V8.20, 30 October 2026

Released 30 October 2026 after owner authorization and all required checks.
This affects Marketing → Catalogues → Preview & Print, not the separate
Crystocraft Range PDF export. No live catalogue/product data migration is needed.

## Behavior

- Selected product photographs use contain fitting in both builder and print.
  The six-photo selection limit is removed. The first selected image remains
  the hero; drag ordering is preserved across continuation pages.
- Automatic pages use four-product overviews for compact entries, two-product
  comparisons for ordinary entries, and single-product features when more space
  is needed. Different photo counts can share a page. Existing item order is
  retained, with no padded empty product slots.
- An optional Feature product selection and Start on a new page checkbox are
  saved only when the operator changes them (`layout_mode`, `page_break_before`
  on the existing catalogue item). Legacy items default to automatic.
- The browser measures the full text in its real, bundled fonts. Long copy is
  promoted to a larger layout or split into labelled continuation pages. Extra
  photographs receive galleries of up to six images. All pages for a product
  remain together. No stored description is shortened, rewritten or migrated.
- Character-preserving splits handle CJK, emoji, newlines and long unbroken
  specifications. Trailing whitespace remains in the DOM without consuming an
  otherwise empty page. Text keeps its normal readable font size.
- Print is enabled only after font, image and final text-bound checks. Missing
  photographs or an impossible heading produce a visible error and block print.
  A direct print while preparation is incomplete shows a preparation notice.
- Fixed A4 landscape pages scale for phone previews. Header/footer, page numbers,
  32px column gaps and 16/24px spacing provide a consistent composition. The
  existing cover, overlay and ink selections remain intact.
- Print CSS is mounted/unmounted with CataloguePreview. Never globally import
  these @page/shell rules: that would affect other document exports (L-30).

## Verification

`npm run test:catalogue-cover` includes real form/cover/builder regressions plus
the pure pagination suite, in prebuild and the required product-search job.
Browser QA uses `node qa/catalogue-layout-preview.mjs`; its synthetic cases have
no live Firebase/Auth dependencies. `--real` can read an existing ignored local
catalogue snapshot for visual comparison. It never writes OC data.

Local browser checks: existing three-product catalogue; four-product overview;
mixed 3/4-photo comparison; 15 + 8 photos in exact order; 13-photo product with
2,320 marketing and 8,225 specification characters, reassembled byte-for-byte;
text-only continuation; invalid-image and impossible-heading print blocks;
375px preview without document overflow. Screenshots/readbacks are ignored under
`qa/out/catalogue-layout/`. Browser page geometry is checked; this is not a claim
that a separately downloaded PDF has been rendered and inspected.
