## Implemented contract

- One server-owned, persisted request per intended order. Ordinary re-entry,
  Back, repeated submits and parallel tabs Open/Resume the same request/result.
- **Create additional order** is explicit, requires a short reason and a current
  conversion revision, and preserves all earlier orders. No unique quote ID,
  remaining-quantity cap, split-order merge or invoice-policy change.
- Prepare freezes the reviewed normalized header/lines, canonical fingerprint,
  complete quote/item source fingerprint and stable operation/order IDs before
  SO allocation. A reused pending request must match those same facts.
- Commit writes SO counter, stable order, its lines, receipt and quote link in
  one Firestore transaction. Retries return the same receipt; no best-effort
  client backlink remains. Missing/mismatched receipt targets require review.
- Unknown responses block fresh Create until a successful saved-state check.
  A saved prepared request can Resume after navigation/reload. Source edits
  require cancellation/review before a fresh request; cancellation retains its
  history and cannot delete an order.
- Quote Duplicate removes conversion ownership fields while retaining its
  existing commercial content/attachment copying workflow.
- Source validity gates fresh creation, not access to saved recovery. If a saved
  request's quote later becomes uploaded/has invalid Range prices, its history,
  Resume and cancellation controls remain reachable; creating a fresh order is
  blocked until source review. The uploaded quote view also links to recovery.

## Ownership and data shape

`/api/quote-order-conversion` is a Node endpoint using the existing Firebase
Admin bootstrap and freshly read profile. Read/mutation require both internal
Shipping and Quotes capability, or admin. Customers/partially authorized staff
are rejected before private data access. No new credentials, dependencies or
SQL RPCs are introduced. All responses are private/no-store.

The endpoint accepts `status`, `prepare`, `commit`, `cancel` and a non-mutating
authorized `ready` probe. Input is bounded to 512,000 bytes and 1–200 order lines;
the source read refuses more than 1,000 quote items. It validates IDs, source
identity, revision, additional reason, prices/currency, source-file shape and
existing order validation before claiming an intent. It never splits an atomic
order commit into partial batches.

Additive private path:
`client_quotes/{quoteId}/order_conversions/{operationId}`. Fields include stable
IDs, initial/additional kind/reason, original conversion revision, source/payload
fingerprints, normalized payload, initiating UID/time, prepared/committed/cancelled
state, result and cancellation audit. It is never stored in customer-readable
order children. Internal views return controlled summaries/history, not actors
or unrestricted private operation documents.

Protected quote fields:
`converted_order_id`, `order_conversion_version`, `active_order_conversion_id`,
`latest_order_conversion_id`, `legacy_converted_order_id`.
Only the endpoint writes these. `converted_order_id` remains the latest committed
order shortcut; private receipts are the full history. Status supports bounded
pagination, including cancelled requests, without losing the latest order.

New orders use `source: in_app_quote`, `client_quote_id` and opaque
`quote_conversion_id`. The last two are provenance IDs, not permission to read
the internal source or request. Rules refuse client conversion creation,
provenance changes and deletion of tracked orders. Commercial edits and existing
invoice reference revision guards remain intact. Quotes with recovery history
cannot be deleted; the UI explains this. Cancelled request history is retained.

`src/shippingModel.js` owns the extracted pure order constants, normalization,
totals and validation shared by browser/server; shipping.js reexports its prior
API. `soNumberModel.js` owns the same HKT year, SO formatting and existing JES
seeds. Existing numbering paths consume those same definitions. The historical
read-only `erp-sync/check_doc_seeds.py` reads the moved SO literal and original
SI literal. No new number series is introduced.

ShipmentForm retains initialization, editable draft state, quote mapping,
validation and navigation. `QuoteOrderRecovery` presents saved quantities/
prices, status, history, Resume and explicit additional-order review.
QuoteDetail's read-only history panel uses the same endpoint; quote-only staff
retain normal quote access without invoking the Shipping-only conversion panel.
Existing manual/PI, Direct Invoice, Shipping Duplicate, Woo, stock and split/
reissued invoice workflows remain outside this fix.

## Legacy handling and cutover limits

An old scalar link is **unverified**, even if its customer matches: the old
Duplicate action could copy it. Show its current target/missing/mismatched state
and retain its identity. Before an additional order, require explicit legacy
acknowledgment plus reason; bind that review to the target's complete current
snapshot. A changed target blocks commit. Capture the old pointer in
`legacy_converted_order_id` and the request's private legacy review. Do not adopt
the old order into verified receipt history, reassign it, or infer missing links
from notes/amounts. No history is automatically migrated on page viewing.

Old conversion tabs submit indistinguishable source-less manual Creates. Rules
block their scalar backlink but cannot reject that Create while preserving
ordinary manual creation. Refresh OC tabs at release cutover. This bounded
limitation remains SH-07; do not claim universal old-client deduplication or
silently disable manual orders. New protected request/receipt fields remain
fail-closed if an older app is reopened. Keep the new rules and receipts during
any fix-forward release; never remove operations or reuse counters as rollback.
