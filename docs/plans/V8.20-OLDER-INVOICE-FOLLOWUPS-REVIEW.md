## Proposed fix

### 1. Bind each action to the invoice the operator chose

Pass the displayed operation ID through both Resume entry points, including the order header. Verify the operation belongs to the saved order and is still its current eligible request before attempting a mutation. A stale or unspecified target should return a refresh message. Confirming a manual review should use the exact ID and SI captured when the form opened. If the current invoice or its reference revision changes during review, show the change and ask the operator to reopen the intended review. Keep the typed reason attached to its original target. Preserve the saved-request retry and the explicit split and reissue actions.

### 2. Show pending follow-ups on the order

Add a visible **Invoice follow-ups** section next to **Invoice status**. Show the exact SI, UC, current or historical designation, pending stage and reason. Make unfinished receipts independently discoverable from the latest-20 history preview. Reuse the closure checklist's server-side receipt classification and provide a continuation or an explicit incomplete result for larger histories. Keep summary CSV and customer routes on their existing visibility rules.

| Situation | Staff action |
| --- | --- |
| Current request with matching saved references and a retryable pending stage | **Resume** for staff with Shipping and UC or an admin. A missing automatic job by itself is compatible with legacy Resume. |
| Another attempt is running | Show **In progress** and refresh the exact receipt before another action. |
| Historical pending receipt, changed ownership or references, conflicting ledger evidence, or unresolved currency or amounts | Show **Finance review needed** and the exact SI and UC for handoff. After Finance has reviewed it, an authorised operator uses **Record Finance review** with a reason. Reuse the existing exact-receipt SQL review fence and preserve previously completed stages. |
| Source unavailable or receipt match uncertain | Show a retryable status and keep mutation controls unavailable until a fresh verified read. |

Keep Finance handoff distinct from recording a completed review. The first release can give staff the exact invoice details for an internal handoff and expose the existing authorised review action outside the closure checklist. If staff still need to find pending work across many orders, review a separate read-only list once the per-order actions are safe.

## Implementation

Both order controls send the selected saved request ID for Resume. The server compares it with the current order pointer before any allocation or financial write. A first-issue retry can continue its matching first request. If the current pointer has advanced to a split or reissue, the old request asks the operator to refresh. The allocation claim readback also checks the intent chosen by the transaction. Refresh existing tabs at cutover to load the pinned Resume and Finance review actions.

The Finance review form captures the selected request ID, SI, UC and saved reference state when opened. Status refresh can invalidate the form while preserving the typed reason with its original invoice. The server rechecks that snapshot. Historical Finance review calls the existing exact-receipt review fence, and it leaves the current invoice and any settled financial stage intact.

The order status endpoint projects pending linked receipts independently of its latest-20 history preview. The order shows which invoice needs Resume, has a leased follow-up in progress, or needs Finance review. A failed status read pauses controls and offers refresh. Staff with Shipping access can see the statuses. Admins and staff with Shipping and UC can act. The checklist scans up to 500 linked receipts and reports when its results are incomplete. Customer routes, summary CSV and approval of invoice originals use their existing scope.

Six local fictional Firestore and PGlite scenarios replayed the original proofs. A stale Resume and an open Finance review carried across a refresh left the replacement's SQL ledger and pending stage intact. An active legacy split with no job resumed the same SI. A historical pending split beyond the history preview appeared in the order checklist and retained its own exact review path. Local evidence is in `qa/out/older-invoice-followups-fix/`.
