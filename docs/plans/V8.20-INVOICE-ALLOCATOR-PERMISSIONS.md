`public.allocate_sales_invoice(text,text,text,text,bigint,text,text)`.

## Exact migration, safeguards and compatibility

The generated migration is
[`20261107180016_harden_sales_invoice_execute.sql`](../../erp-sync/migrations/20261107180016_harden_sales_invoice_execute.sql).
Its transaction:

1. Limits lock wait to five seconds and statement execution to fifteen seconds.
2. Refuses a missing function, unreviewed overload, changed owner, SECURITY
   DEFINER setting or pinned search path.
3. Revokes only this function's privileges from PUBLIC, anon and authenticated;
   retains/grants its existing service_role execution.
4. Checks effective rights, including inherited role access, before commit.
   Any mismatch rolls the entire ACL change back.
5. Confirms the function definition is identical and notifies PostgREST to reload
   its schema cache. The operation is safe to reapply.

No function is recreated, no body/signature/owner/search path changes, and no
table/schema/default privileges, role memberships, rows, sequences, SI/UC numbers
or Firestore references are modified. The owner retains implicit administrative
rights. There are no new keys, broader raw-schema grants or authentication rules.
Existing authorized OC clients, including older open tabs, still use the same
gateway/signature/service grant. Intentional multiple/split/reissued invoices
remain supported. Durable allocation/recovery is **SH-05B**, not this change.

Canonical `erp-sync/app_sales_invoice.sql` now removes PUBLIC on both the legacy
six-argument definition and the final seven-argument definition. Each definition
and its grants are transaction-wrapped, so an interrupted setup cannot commit a
new publicly callable allocator. **Do not replay that historical setup file on
production**; apply only the reviewed narrow migration. Its existing table/audit
setup and allocator bodies remain otherwise unchanged.

## Fictional verification

`npm run test:invoice-allocator` runs **18 tests** against actual, disposable
in-memory PostgreSQL **17.5** through pinned test-only PGlite **0.3.15**. It has no
network connection or production credentials. The test reproduces inherited
PUBLIC execution with fictional SI/UC records, then proves:

- anon/authenticated/unrelated direct calls fail with SQLSTATE 42501 before any
  number/data/sequence changes; explicit named grants are removed too;
- the service account can still allocate using the unchanged function, reuse
  UC ID/text or preserve unresolved historical UC text, without direct raw-schema
  access; deliberate repeated invoices remain possible;
- function definition/OID/owner/configuration, existing rows, audit rows,
  sequences and table/schema ACLs survive the migration unchanged;
- extra overloads or changed security configuration stop before mutation;
  unexpected inherited service access aborts and rolls the ACL transaction back;
- reapplication is harmless; fresh canonical setup is private and interrupted
  canonical installation cannot expose a public allocator;
- the **actual OC UC client and edge handler** reach real fictional SQL through
  a constrained local REST adapter, preserving payload/results/audit identity;
  UC-authorized staff are allowed and other staff/customers are refused, including
  customers carrying forged module values. A bad server grant reports failure.

JWT/profile verification and REST transport are fictional in these local tests;
this is not live Firebase, TLS, PostgREST or production allocation certification.
They execute real PostgreSQL roles, ACLs, transactions and allocator logic, and
run within existing `test:invoice-reconciliation` in prebuild and product-search
CI. No Docker/server installation or listening database is required.
