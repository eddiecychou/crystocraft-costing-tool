# V8.19 dashboard summary update status

25 October 2026. Release preparation; candidate/production gates pending.

## Behaviour

The dashboard previously owned its running/progress/error state. Navigating away
did not cancel the underlying browser generation, but returning reset the UI and
enabled a second Update. `src/summaryUpdate.js` and `useSummaryUpdate` now own one
in-flight generation per tab outside page lifecycle. Dashboard subscribes through
useSyncExternalStore. State retains the source period, current progress and errors.

A shared promise is acquired before notifying subscribers or starting generation,
so rapid or remounted starts cannot duplicate it, even with a different period.
Update and conversation-window controls remain disabled while running. Collapsed
Summary settings shows Updating, and a visible status paragraph includes the active
period and customer progress. Completion clears running state and uses the existing
Firestore cache listener, avoiding a stale component publishing an optimistic result
for a different period. Failures remain visible after return and unlock retry.

This is same-tab SPA navigation persistence. Reload/closing the tab can still
interrupt the client job; no running flag is persisted across a new runtime.
No server job, storage/schema/rules change, AI prompt/source changes, task/Pipeline
mutation or automatic generation is introduced. V8.19 remains the release cycle.

- Four pure store cases: route subscriber removal/re-add with progress retained,
  duplicate starts across periods, completion, retained error/retry, fresh runtime
  idle state, stable snapshots, invalid period and re-entrant duplicate prevention.
- 48 focused store/summary/Pipeline tests PASS; new tests included in prebuild.
- Actual Dashboard + Layout Chrome fixture with real summary orchestration:
  leave during first batch, return with collapsed Updating label and disabled
  Update/period controls, attempted duplicate click does not start a batch;
  return during second batch retains 3-of-4 progress; complete while away and
  return to all four saved summaries; fail while away and return to retained
  error/previous cache; retry clears error and unlocks after success.

  Zero runtime errors, live AI calls or live data writes in the fictional fixture.
