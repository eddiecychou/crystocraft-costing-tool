# V8.20 — Unicode image download filenames

Status: released and verified on production on 30 October 2026. Both required
GitHub jobs passed before candidate/production uploads; both roles and all five
actual Chrome downloads passed after publication.

## Report and diagnosis

Carry-Loop Water Bottle — 600 mL (ZC-047) displays all five product photos, but
Chrome reports “Site wasn't available” when downloading them. Read-only live
requests for the same fourth image reproduce HTTP 500 with the original em dash
in its filename and HTTP 200/image/jpeg with a plain ASCII filename. The image
itself is valid.

`download-image.js` placed the unencoded product-derived filename directly into
`Content-Disposition`. Constructing the response throws a ByteString error for
U+2014 (and other Unicode characters), after successfully retrieving the image.

## Correction

The shared download endpoint now returns a quoted ASCII fallback plus the real
filename encoded with RFC 5987 `filename*=UTF-8''…`. Path separators and control
characters are sanitized, quotes cannot terminate the fallback, and truncation
does not split Unicode code points. Normal names retain their spelling.

The existing HTTPS, first-party host/bucket, redirect, timeout, size and optional
image re-encoding policies remain in place. No product names, uploaded assets,
visibility, pricing, Firestore records or security rules were changed.

## Verification

- The actual handler regression fails before the correction with the reported
  em dash/ByteString error and passes afterward.
- All nine download tests pass: the reported filename, Chinese/accented/emoji
  names, quoted/control/path input, empty/long names, rejected source URLs,
  upstream errors/oversized responses and existing normalization behavior.
- `npm run test:product-images`: 32/32 pass. The download suite is now included
  in this existing prebuild and GitHub workflow step, rather than left standalone.
- Full `npm run build` (including prebuild) and repository no-undefined lint pass.
- The corrected local handler fetched all five actual product images through
  the existing production Image CDN: HTTP 200/image/jpeg, preserved Unicode
  attachment names; all five saved copies decode as 1000 × 1000 JPEGs.
- Ignored evidence/local copies: `qa/out/image-download-fix/`. It contains source
  asset URLs/tokens; do not commit it. Candidate and production evidence is
  recorded separately below.
