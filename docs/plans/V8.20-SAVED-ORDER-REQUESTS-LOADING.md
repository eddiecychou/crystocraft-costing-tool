# Saved order request list loading

**Release update — 12 November 2026:** published in the combined [Shipping recovery release](V8.20-SHIPPING-RECOVERY-RELEASE.md), source `443173e`. The implementation-stage results below are historical; the linked release record contains current CI, migration, role and preservation evidence.

**Implemented locally, 9 November 2026.** This is a follow-up to the local
manual/PI, Duplicate Order and initial Direct Invoice recovery work. Those
Shipping changes await their own release. The Portal alert release did not
publish them.

## Finding and scope

Shipping and Sales Invoices share `SavedOrderRequests`. Its original loading
handler allowed a response from an earlier open of the panel to replace the
newer list. A fictional regression reproduced this by completing the newer read
first and the older read last.

The handler also retained state across operator changes, allowed overlapping
pagination reads before React disabled the button, and retried the first page
after a later page failed. These paths now have dedicated fictional regressions.

## Ownership

`src/components/shipping/SavedOrderRequests.jsx` owns the disclosure, pending
read, page cursor and visible error. Its inner panel is keyed by operator.
Closing or unmounting abandons the current read. A response may update rows,
errors and loading only while it still owns that read. One active read blocks
another pagination request. Retry retains the failed cursor and the existing
rows until the requested page succeeds.

The existing `orderRequestAction` transport, request URL model, server-managed
creation requests, invoice operations and SQL receipts retain their ownership.
The panel continues to show Resume/Open using the existing request and initial
invoice states. The change concerns loading the list and navigating its links.

## Verification

`qa/saved-order-requests.test.mjs` renders the actual component and Router with
deferred fictional transport responses. Five bounded cases cover reordered
reads after reopen, stale failures, empty state, pagination failure/retry,
rapid duplicate clicks and operator changes. They verify the operator in the
resulting request URL and the existing Direct Invoice Resume label.

`npm run test:order-create` passed all ten request-model/endpoint/component
tests. The full production build passed all 1,141 prebuild tests with zero
failures or skipped tests. Touched-component no-undef and `git diff --check`
passed. Logs are in ignored `qa/out/sh07-direct/saved-request-*.log`.
