# Packing List access for Shipping-only staff

The Packing editor now loads saved plans and standard carton data independently.
Shipping-only staff can open, edit, star and export saved plans and create a
manual plan. The standard generation controls explain when catalogue access
is required. A temporary lookup failure has its own Retry and leaves the
Packing draft available. Staff with catalogue access still use the same
standard packing calculations. Firestore rules and role grants are unchanged.

## Fictional verification

Two headless Chrome sessions used the real editor, Freight comparison and
exports with the Web SDK and Firestore rules on a local emulator. One actor
had only Shipping access. The other had Shipping and Figurine access.

| Check | Result |
| --- | --- |
| Catalogue access | Shipping-only Range read denied. Shipping plus Figurine Range read succeeded. |
| Shipping-only | Opened, edited, saved and reopened an existing plan, then exported it. Starred another plan and verified the new default in the other tab. Created and reopened a first manual plan on a second order. |
| Shipping plus Figurine | Generated two cartons of 12 pieces using the saved dimensions, weight and packaging code, then saved, reopened and exported the plan. |
| PDF and Excel | Both PDFs rendered as single landscape A4 pages with their scenario-specific cargo. Each downloaded workbook was parsed and verified for item, unit, quantity, total and vessel. PDF pages were rasterized and inspected. |
| Freight | Full saved quote and decision snapshots matched before and after, including cargo, stored USD and HKD prices, quote links and selection. The new-quote form followed the working Packing plan and its saved totals. |

All 32 Packing and Purchase Order checks, 29 Packing and Freight emulator
regressions, 11 Firebase configuration checks and undefined-variable lint
passed. The added page regression covers pending catalogue data, temporary
failure and retry. Local artifacts are under the ignored
`qa/out/packing-staff-fix/`.
