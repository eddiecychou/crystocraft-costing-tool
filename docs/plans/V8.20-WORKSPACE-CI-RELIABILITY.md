## Confirmed repair: deadlines outside the awaited workload

The old eventually helper checked its 10s deadline only around an awaited act
call. If that call never returned, the clock was never checked again. Setup,
reads and process completion also had no independent wall deadline. These are
confirmed harness defects even though the intermittent event triggering them
was not observed. A same-thread timer also cannot interrupt a busy JS loop.

The named 15s steps and 45s summary-case bound are now backed by a separate
parent-process 90s wall deadline for the full page suite and each timezone run.
qa/test-process.mjs launches the original Node tests, preserves failures and
terminates only its owned process group on timeout (Mac/Linux), including the
Node test worker/descendants. It throws QA_PROCESS_TIMEOUT; no force-exit-to-
success or test skipping. qa/run-workspace-page-test.mjs and the timezone
runner use it. The job's 10-minute limit is unchanged.

The stronger real-Node-worker regression caught a new-launcher trap: inheriting
NODE_TEST_CONTEXT from a parent test worker can make a nested --test launch
return success without running its cases. The launcher now removes that
internal context from its copied child environment. The regression deliberately
supplies it and requires the real blocked worker to run and hit the deadline.

Eight guard cases cover result/error identity, a blocked promise, a real busy-
loop Node test worker, failed exit-code propagation, descendant heartbeat
termination and invalid/unbounded deadline rejection. They pass under Node
22.23.4; no blocked workers remain. Existing 63 assertion expressions are
syntax-tree identical after removing source positions/the diagnostic wrapper;
this is a source-expression count, not a runtime assertion count. All 22 real
page cases and 11 cases per timezone remain. Bundles now use unique ignored
qa/out/workspace-sync-* scratch directories, so an interrupted test cannot
leave an untracked executable in the release checkout.

The complete guarded emulator sequence passes locally, as does the final
workspace command with all 63 cases (8 guard + 22 page + 33 timezone). Final
source SHA, both GitHub job results and production-unchanged readback will be
recorded after final CI. The intermittent trigger remains an open observation
item; guard success is not proof it can never recur.
