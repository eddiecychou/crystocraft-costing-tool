# V8.19 dashboard customer actions first

20 October 2026. Implemented locally; candidate/production gates pending.

## Behaviour

The owner's workflow is a customer-based to-do list, with summaries read
occasionally to plan new follow-ups. Previously every digest preceded its tasks,
and summary settings/update instructions occupied the top of the shared panel.

The default dashboard is now Customer to-do list. Its customer picker remains
immediate, with exactly one pinned workspace when chosen. Each card has:
- To-do first, retaining the existing overdue/today/waiting/date ordering and actions.
- Reference notes in a separate section when present; the note editor stays there.
- Email & conversation summary in a quieter, labelled reference panel below work.
  It includes email, WhatsApp and interactions, so the label preserves that scope.

Dashboard previews use 200 characters, with Read full summary / Show less, full
saved text, accessible 44px controls and a manual Add task workflow. No AI rewrite
or regeneration is needed. Customer Detail shares action-first structure but retains
its existing 500-character preview; individual channel summaries and commitments
keep their existing behaviour.

Unfinished customer tasks, including undated and Waiting work, appear before
summary-only customers. The owner's selected customer still takes precedence.
Summary period/update controls are behind Summary settings, closed initially;
cache timestamp appears there once rather than repeating on every dashboard card.

This is presentation and view ordering only: task identities/revisions, task/note
transactions, legacy follow-up history, listeners, summary caches/prompts, ingestion,
Pipeline decisions, due counts, Hong Kong dates and RBAC are unchanged. No Firebase
rules release or production work-item/summary migration.
