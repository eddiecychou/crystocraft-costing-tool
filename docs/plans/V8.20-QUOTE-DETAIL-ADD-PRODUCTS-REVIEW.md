# Quote Detail → Add Products review

26 November 2026, Australia/Sydney. Reviewed OC at `132d623b`, after
the New Quote exchange-rate release. Fifteen fictional scenarios used
the real Quote Detail and catalogue picker in Chrome, with Firestore
reads, listeners and writes handled by an in-memory fixture. The browser
could reach only the loopback test server. The export check captured the
header and rows passed to the export dialog. Write failures and a lost
confirmation were injected at the fixture boundary. No live quote,
catalogue entry, Settings document or permission was changed.

## Exchange rates and prices

The control quote had one existing line at EUR 12.34, agreed USD and EUR
rates of 8.25 and 9.45, and current Settings rates of 9.10 and 12.00.

| Fictional case | Observed result |
| --- | --- |
| Add Corporate Gifts and two Range variants with agreed rates | The Corporate Gifts tier of HKD 94.50 saved at EUR 10.00. Range variants listed at USD 10 and USD 12 saved at EUR 8.73 and EUR 10.48, using the saved quote rates. Both variants shared a SKU and had distinct indexes, and both saved. The original EUR 12.34 line and agreed rates reached export intact. |
| Corporate Gifts supplier costs | Two USD 10 parts and USD 5 tooling saved as HKD 182.00 unit cost and HKD 45.50 tooling, using current Settings. The EUR 10.00 selling price still used the agreed quote rate. |
| Positive numeric strings on an existing quote | Stored rate strings `"8.25"` and `"9.45"` produced the same selling prices and retained their exact stored values. |
| Legacy quote missing the agreed EUR rate | The Corporate Gifts line saved the HKD 94.50 amount as EUR 94.50. The 1:1 fallback produced a plausible amount in the wrong currency. The Range line saved with a blank price and the existing Range export guard stayed active. |
| Legacy tier already priced in the quote currency | The explicit EUR 14.25 price saved as EUR 14.25 even with the agreed EUR rate missing. This case needed no selling-price conversion. |
| Settings document missing | The Corporate Gifts cost calculation silently used the hardcoded USD 7.78 fallback, recording HKD 155.60 for parts and HKD 38.90 for tooling. The EUR 10.00 selling price was preserved. |
| Settings present with USD missing or stored as text | Adding the Corporate Gifts item alone saved nothing. The error went to the browser as an unhandled rejection. The open picker offered no failure message. |
| Settings access failed with HKD-only supplier amounts | Adding the Corporate Gifts item still failed because it always reads Settings. The parts and tooling needed no currency conversion. |
| Range SKU has no listed wholesale price | The line remained available for staff to price manually. It saved a blank price, with the existing export guard active. |

The Corporate Gifts path reads current Settings for internal costs and
the quote header for selling prices. Its own fallbacks explain the
different failure cases. The Range path keeps the chosen variant and
wholesale-to-quote conversion in `rangeQuoteItem`.

## Partial saves and retries

Each mixed selection contained one Corporate Gifts item and one Range
variant and started from the same one-line quote. **Rows** counts saved
line documents, including the original. **Header** is the saved
`item_count`, which the Quotes list displays.

| Action or injected fault | After first attempt | After retry |
| --- | --- | --- |
| Range saves while Corporate Gifts waits for Settings, then the required USD rate is missing | 2 rows, header 1. The picker still says 2 selected even after the saved Range row is hidden. | After supplying USD, retrying in the same picker saves a second copy of the exact Range choice. 4 rows, header 4. |
| Same failure, then close and reopen the picker | 2 rows, header 1. | Reopening excludes the saved Range choice. Selecting only Corporate Gifts gives 3 rows, header 3. |
| Corporate Gifts line write rejected | 2 rows, header 1. | Same-picker retry saves the Corporate Gifts line and duplicates the Range line. 4 rows, header 4. |
| Header update rejected after both lines saved | 3 rows, header 1. | Same-picker retry duplicates both lines. 5 rows, header 5. |
| Confirmation lost after both lines and header committed | 3 rows, header 3. The picker stays open. | Same-picker retry duplicates both lines. 5 rows, header 5. |
| Second Add click while the first Corporate Gifts read is pending | Two submissions proceed without a busy guard. | Both catalogues save twice. The two header updates write counts of 3 and 4, leaving 5 actual rows and a header count of 4. |

The picker filters its list against saved quote identities, but it keeps
the original selection in state. Add passes that selection back on every
click. Quote Detail starts independent writes and updates the header only
after those promises all resolve. A rejected promise leaves any earlier
writes in place. Neither the picker nor the handler provides progress or
a visible error for the failed attempt. Every fixture retained the
original line and agreed rates.

## Proposed fix

1. **Prepare the whole selection before writing.** Resolve the quote's
   saved selling rates and the required Corporate Gifts supplier rates
   independently. For conversions, validate finite positive saved quote
   rates, including valid legacy numeric strings. Retain an explicit tier
   already priced in the quote currency. If a legacy quote needs a rate
   and lacks it, name the currency and keep the selection available for
   review. Leave agreed rates and existing prices alone. Keep the manual
   price path for genuinely unpriced Range items and its export and PI
   safeguards.
2. **Share the Settings read for supplier costs.** Use the same configured
   rate validation as New Quote and Corporate Gifts Pricing, with one
   server read per selection that requires a foreign supplier rate. HKD
   part and tooling amounts need no exchange-rate read. If a required
   cost rate or supplier-cost source cannot be verified, identify the
   affected item and pause the selection before any write. The quote's
   agreed rates still own the selling price. The rules currently grant
   catalogue and tier reads to quotation staff and restrict supplier
   costs to supply staff. Keep those permissions and test a restricted
   role alongside an authorized costing role.
3. **Save lines and the header together.** Use the existing quote and item
   documents. Reuse `quoteItemKey` and the picker’s legacy matching rules.
   Give new catalogue lines stable IDs derived from their exact choice so
   a repeated click or a retry after an uncertain response can recognize
   a saved line and retain its stored price. Keep distinct Range variants
   with the same SKU selectable. Read the quote header and verify that its
   currency and saved rate inputs still match the prepared selection.
   Check the current saved lines, including existing random-ID documents,
   before writing missing lines and the resulting `item_count` together in
   one transaction. Use the quote header to coordinate competing adds.
   Exercise concurrent Custom Item adds and line removals during the
   implementation review, since those currently write the line and count
   separately. Coordinate count updates if the test exposes a race.
4. **Make retry explicit.** Disable repeat submits while the selection is
   pending, show actionable validation and save errors, and retain the
   selections. After an uncertain result, read back the exact saved
   choices and count before offering another write. A repeated request
   should return the saved result or add only genuinely missing choices.
   Leave historical duplicate lines and unrelated quote fields for their
   existing workflows.

## Local implementation and verification

Add Products now prepares the entire selection before saving. It uses the
quote's agreed rates for selling prices and one shared Settings read when
foreign supplier costs require it. A missing or invalid required rate
leaves the selection available for review. A direct price in the quote
currency and a Range line awaiting manual pricing keep their respective
workflows.

The transaction saves new lines with stable catalogue IDs and updates
`item_count` from the current stored lines. It checks the current header
against the agreed rates used for preparation. Legacy random IDs and
SKU-only rows remain recognizable. Custom Item and Remove share the
header transaction so their count updates coordinate with Add Products.
The picker disables repeat submission and retains selected products after
an error. A retry reads the saved choices before reloading any rates.

- Ten loopback Chrome scenarios covered mixed selections, missing and
  rejected Settings, valid agreed prices through export, an atomic write
  rejection, and a lost confirmation. Retrying the lost confirmation
  left the original line and two selected lines at a count of three.
  The retry made zero additional writes and performed no Settings read.
- Nine real Firestore SDK and rules cases passed with fictional records.
  They covered a rejected commit, concurrent overlapping selections,
  custom add and removal races, deliberate re-add, stale agreed rates,
  legacy identities and the quotes-only staff access boundary.
- The local build and all 1,301 prebuild checks passed. Browser and
  emulator logs are under the ignored
  `qa/out/quote-detail-add-products-review-2026-11-26/` directory.

The fix is local. Existing quote records require no migration. These
checks exercised the updated editor. A browser still running an older
build would continue to use its previous independent-write handler.
