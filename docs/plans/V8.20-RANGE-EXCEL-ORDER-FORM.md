## Compact buyer workflow

**Crystocraft Range → Download catalogue → Excel order form**. Select an approved
trade account for its customer prices/currency and choose the current filtered
selection or all visible products. Filtering includes products beyond the first
screen/page. Hidden and sold-out/retired products remain excluded. PDF stays in
the same dialog with its existing pricing and variant labels.

The file has one **Order form** sheet: a small title/customer header, a fixed
total, photo, product/code/size, exact crystal option/finish, unit price, colour
quantity columns, row quantity and amount. Enter whole quantities in blue cells.
Unavailable combinations are blank grey cells. The product/price columns and
four header rows stay frozen. Source codes and premium-price options remain
distinct; exact selected-colour SKUs are in the input messages.

The revision removes the buyer-information form, duplicate finish text,
MOQ/lead-time/stock-count paragraphs, filter arrows, review counters, repeated
"Order qty" labels and the Colour guide tab. Regular rows are shorter, photos
keep their aspect ratio, and long English/Chinese labels continue visibly onto
additional rows. The Swan example keeps its same 38 priced options, 26 colours,
393 editable quantity cells and 38 photos. Visible column widths reduce from
448 to 343 Excel width units, without dropping products or colours.

Only exception information is shown: relevant price/amount cells are highlighted
and one short footer message asks for confirmation. A single hidden column holds
buyer-safe validation/availability calculations; it contains no supplier data.
Normal buyers see the order grid and totals. Sheet protection prevents accidental
price/formula edits; it is not the privacy boundary.

Prices use the existing account WS percentage and fixed/global FX helpers, then
the existing display precision (HKD one decimal, others two). Only the exported
snapshot is rounded; saved prices are untouched. Missing prices/FX, Concepts and
amounts that would display as zero require a quotation. Positive unpriced lines
show **Quote required**, and the total is labelled **Priced subtotal** with a
short explanation, so they cannot appear to be free items. Invalid pasted text,
negative or fractional quantities show **Check quantities** instead of a
plausible numeric total. Explicit whole-number validation also blocks normal
invalid entry in Excel.

Retired-stock warnings still combine all colours/premium options for the same
product/finish, using existing component-driven availability. Unknown stock
remains unknown; the old finished-stock field is not used. "Limited stock" is
the only routine stock label. MOQ and lead-time text is omitted from this simple
form; no new minimum or colour-mixing policy is enforced. Prices are valid 30
days, with final pricing/availability confirmed on acceptance. The workbook does
not create an order or reserve inventory.

## Ownership, privacy and migration

- `src/rangeOrderForm.js`: explicit buyer-field projection, source option/colour
  identity, customer prices, visibility and stock pools.
- `src/rangeOrderFormExcel.js`: existing ExcelJS writer, typed values, formulas,
  protection/validation, compact layout, aspect-fit photos and continuation rows.
- `src/rangeCatalogueLabels.js`: authoritative existing PDF/Excel label rule.
- `src/components/RangeCatalogueExport.jsx`: shared PDF/Excel dialog, account and
  scope, bounded image loading, single-flight build and close/unmount cancellation.
- `src/pages/Range.jsx`: passes all filtered IDs and raw nullable availability.

No migration, collection, endpoint, business-record write, price publication or
rules change. Products/BOMs/supplier costs/internal notes/source attachments/full
account profiles are never written to visible or hidden workbook cells, names,
comments or ZIP parts. Existing customer-visible product photos are used.
Uploading, marketing enrolment, outreach and order import are outside this flow.

## Verification and lessons

`npm run test:range-order-form` is part of prebuild and the required GitHub
`product-search` job. Nineteen actual model/writer/dialog tests use fictional
records and only I/O boundaries substituted. Coverage includes account pricing,
exact display rounding, fixed/missing FX, source identity, repeated SKUs, premium
options, leading zeroes, visibility/Concepts, unknown/shared stock, typed values,
formulas, privacy across every ZIP part, long English/Chinese text, photo aspect,
compact structure, current/all/empty scope, PDF parity, loading/cancel/double-click
and failed reads/images.

The independent spreadsheet engine recalculates seven compact cases, then saves
and reopens the actual generated fixture: 12 pieces, USD 57.45 priced subtotal,
two unpriced pieces and an explanation; six basic plus five premium pieces warn
against one shared ten-piece stock pool; invalid input suppresses a numeric total.
A QA-only preview adapter feeds the new production writer with the same buyer-safe
data/photos from the earlier actual Swan download for a like-for-like layout view.
The release check must use the actual new browser download, not that adapter.

Key rules: preserve source option identity and premium colour prices; calculate
from the visible unit price; never turn null stock into zero; keep all supplier
data out rather than hiding it; guard against Excel SUM ignoring pasted text;
retain all long labels with word-boundary continuation. ExcelJS does not expose
calcMode, so standard OOXML auto/full-calc flags are written and checked.
