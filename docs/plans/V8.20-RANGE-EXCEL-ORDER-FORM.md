# V8.20 — Crystocraft Range Excel order form

Owner authorized implementation, push and deployment on 9 November 2026, after
both required GitHub jobs pass. This is a buyer worksheet export, not an order
import or stock reservation. Release evidence is recorded below after checking
the exact candidate and production artifact.

## Buyer workflow

On Crystocraft Range, choose **Download catalogue → Excel order form**. Select
the approved trade account to use that buyer's prices/currency. The default
scope is the current filtered selection, including products beyond the first
screen/page; **All visible products** is an explicit alternative. Hidden and
sold-out/retired products are excluded. PDF remains in the same dialog.

The **Order form** sheet has a photo, product/code/size, crystal option/finish,
unit price, a quantity column for each available colour, row quantity/amount
and an order check. Premium crystal price options and distinct stored options
remain separate rows, even when their legacy SKUs repeat. Exact colour SKUs
are available in the quantity-cell input messages. The **Colour guide** gives
names, codes, representative swatches and short ordering instructions.

Blue quantity and buyer-detail cells are editable. Grey combinations are
unavailable. Frozen product columns/header, filters, wrapped labels and visible
continuation rows support wide forms and very long specifications without
shrinking/cropping images or silently dropping text. Formula/price protection
prevents accidental editing; it is not a confidentiality control.

Whole quantities of zero or more are accepted. Row amounts and top quantity /
priced subtotal recalculate automatically, including after reopening. Pasted
invalid text, negatives or fractions flag **Check quantities** and suppress a
plausible numeric grand total. Missing prices/FX and Concepts show **Quotation
required** or enquiry notes; they never become free items. Unquoted quantities
and review rows remain visible alongside the explicitly named priced subtotal.

Prices use the existing WS percentage and per-account fixed FX/global currency
helpers, then the same currency display precision (HKD one decimal, others two)
in the exported snapshot. Stored prices are untouched. Positive amounts that
would display as zero remain unquoted. Retired-stock limits combine all colour
and premium option quantities for the same product/finish, using existing
component-driven availability, not the old finished-stock field. Unknown/null
availability remains unknown. Stock is indicative and requires confirmation.

MOQ and lead weeks are informational. The owner has not confirmed colour-mixing
minimums; no per-colour/per-row MOQ policy is invented. Prices are valid 30 days
from issue. The buyer returns the completed workbook for human review.

## Ownership, privacy and migration

- `src/rangeOrderForm.js`: explicit buyer-field projection, priced option/colour
  identity, customer price snapshot, availability pools and visibility.
- `src/rangeOrderFormExcel.js`: existing ExcelJS infrastructure, typed values,
  formulas, validation/protection, aspect-fit photos and long-text continuation.
- `src/rangeCatalogueLabels.js`: shared existing PDF label rule, unchanged.
- `src/components/RangeCatalogueExport.jsx`: one export dialog, account/scope,
  bounded photo loading, single-flight builds and cancellation on close/unmount.
- `src/pages/Range.jsx`: passes all filtered IDs and raw availability (including
  unknowns), rather than exporting only paginated cards or manufacturing zero.

No migration, new endpoint, collection, business-record write, rules change or
supplier-data export. Full products, BOMs, costs, internal notes, supplier
attachments and full account profiles never enter the workbook model, hidden
sheets, names, comments or ZIP parts. Existing public product photos are used.
No messages are sent and no customer registration/marketing state is changed.

## Verification and maintenance

`npm run test:range-order-form` exercises the actual model, workbook writer and
React export dialog with fictional records and only I/O boundaries substituted.
It is part of prebuild and the required `product-search` GitHub job. Covers
percentage/fixed/missing FX, exact price rounding, repeated SKUs, premium options,
brand/code leading zeroes, Concepts/visibility, unknown stock, shared stock,
numeric types/formulas, validation/protection, long Chinese/English text, images,
privacy across every workbook ZIP part, current/all/empty scopes, PDF parity,
metadata loading, cancellation, double-click and failed reads/photos.

Independent spreadsheet-engine QA imports the **actual exported** fictional
workbook, enters quantities, recalculates seven cases, saves/reopens it and
checks the result. A mixed order totals 12 pieces, USD 57.45 priced subtotal,
two unquoted pieces and one review row. Six basic plus five premium pieces
correctly warn against a shared ten-piece finish pool.

Lessons: retain source option identity rather than collapsing by SKU or finish;
round only the exported price exactly as displayed, and calculate amounts from
that visible price. Do not convert null availability to zero. Guard totals even
when a pasted invalid string is ignored by Excel SUM. Count the known review
messages explicitly: the independent engine's wildcard COUNTIF / range-string
comparison handling differs from Excel. Empty buyer inputs are true blank
cells; inspect source XLSX values separately from third-party render artifacts.
ExcelJS does not expose calcMode, so write/verify standard OOXML auto/full-calc
flags rather than assuming cached zero totals will refresh in every viewer.

Local evidence stays in ignored `qa/out/range-order-form/`. Never commit buyer
workbooks, credentials or private record snapshots.
