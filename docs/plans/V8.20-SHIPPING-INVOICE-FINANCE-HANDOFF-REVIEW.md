## Proposed workflow

1. **Shipping captures the handoff.** Record the issue shown, exact saved request ID, OC order ID or SO reference, and the time checked. Include the SI and UC when verified and label any reference copied from unverified saved data as such. A ledger-first handoff starts from the OC ledger source and exact SI, with the ledger row ID when available. Use an existing internal handoff channel to start.
2. **Finance verifies the same invoice.** Start from the exact request ID for Shipping flags or the exact ledger SI for ledger-first cases. Match the SQL receipt to the ledger invoice row ID, SI, order ID and UC, then compare the saved request and current order pointer where they exist. Record which sources were checked and whether evidence is verified, missing, conflicting or temporarily unavailable. The UC, customer name, amount or currently displayed SI alone cannot identify the intended split or reissue.
3. **Finance records an outcome with a reason.** Assign the decision to a designated Finance reviewer. Record the evidence checked, the reviewer, the time and the exact case identity. The outcomes are **Verified, still unlinked**, **Already linked**, and **Needs more evidence**. Record along with the outcome whether information was sent back to Shipping. A missing order or saved request, a replaced pointer, and conflicting ownership or receipt evidence stay unlinked. Retry unavailable checks before reaching a decision. The existing **Resume saved request** and **Review references** actions remain available to the authorised operator only when the existing exact-request checks pass.

### Smallest implementation to consider next

1. **Read-only exact lookup for Finance.** Give invoice-authorised staff a bounded lookup from Sales Invoices, using the saved request ID or exact OC SI. Show a minimal exception result beside the existing summaries. Disclose verified identifiers and source availability. Keep private SQL request and snapshot data server-side. A request ID with no surviving Firestore document or an SI with no SQL receipt should return a clear evidence status.
2. **Copy handoff details in Shipping.** Reuse the flag's existing identity and evidence labels. Keep the first implementation limited to user-initiated copy and lookup. If the team needs shared tracking after using that workflow, agree Finance reviewer access, case ownership and an audit trail before adding a recorded decision in OC.

## Exact lookup and handoff copy

Open **Finance invoice lookup** on Sales Invoices and enter the exact OC SI or saved request ID. The lookup reads the existing OC ledger, allocation receipt and the matching Shipping records. It returns only the evidence status and available identifiers. A ledger match can appear even when the standard invoice summary excludes it. If an SI has no discoverable saved request under its ledger order, the lookup reports the ledger match and asks for the request ID to confirm further evidence. A known request ID can still find the SQL receipt when its Firestore request is missing. A source failure is retryable.

Shipping can copy the issue, order and request references, checked time, and available SI and UC from Finance review rows in **Awaiting order link** and **Invoice follow-ups**. Verified awaiting-link references and saved follow-up references are labelled separately. The button copies only to the clipboard and offers selectable text if the browser blocks clipboard access. Staff use their existing internal handoff channel.

The lookup uses the existing Invoices permission. The copy uses the existing Shipping permission. The case remains read-only across both views and existing recovery controls continue to enforce their own permissions and checks. No rules, database grants or schema migration are required.
