# V8.19 Crystal Components catalogue

19 October 2026. Implementation complete locally; release verification in progress.
This continues the owner's requested catalogue build after the Firebase swatch release.

## Delivered behaviour

OC navigation now opens **Crystal Components** at /crystal-components. Swatch Library
remains accessible from this catalogue and at its original URL. The existing swatch
capability manages product descriptions, real variants, photographs and publication;
Supply separately reviews canonical inventory links. No user module lists change.

The approved-customer catalogue at /shop/crystal-components separates cut components,
fabrics/surfaces and original Swarovski / Strass clearance. Original stock has an
immutable separate origin and must remain stock only. Publication requires an inspected
condition, reviewed provenance/article, real cover photo, confirmed primary variant,
and a Supply-reviewed primary inventory mapping. It does not claim worldwide retirement.

Product media uses Firebase, immutable original/display/thumbnail revisions, checksum
readback and authenticated reads. A failed upload can retry its pending revision.
Archive the product or change its cover/primary variant before archiving those children.
The original Fly renderer and all existing swatches remain intact.

Enquiries retain exact product/variant/sample revisions, descriptions, units, application
and notes. Optional PDF/photo drawings are private to the submitting approved account
and OC admin, never part of the published library. All-unpriced enquiries display
**On quotation** and save a null estimate. Existing priced Range behaviour is preserved.
Favourites open component options rather than submitting an incomplete selection.
Selected published catalogue PDFs contain original photos, specifications and brand
identity, with no selling prices. PDF export rechecks publication and refuses an incomplete
image export rather than silently issuing an inaccurate catalogue.

Availability resolves private per-variant links on the server, returning only approved
stock-minus-reservations quantities and units. No catalogue stock balances, opening
counts, reservations or stock movements are created by an enquiry or catalogue edit.
Existing shared crystal inventory remains canonical. Acceptance/reservation/issue stays
operator-reviewed through the existing stock process; this release does not add an
automatic order/quote adapter or fix the pre-existing generic ledger oversell limitation.

## Customer-photo issue caught before app production publication

The populated candidate's fresh customer PDF/photo gate failed (HTTP 403). The first
Storage design checked users/profile + product + image: three distinct Firestore
documents, while live Cloud Storage cross-service rules allow two. The emulator
accepted this, demonstrating why live role checks remain mandatory. No production
app push followed that failure.

Correction: direct product Storage customer access stays denied; a narrow Node
/api/crystal-product-media gate verifies the revoked token, current role/approval,
product publication, image publication and exact immutable current path before reading
bytes from the fixed bucket. Swatch staff can read pending bytes only under an existing
product/image identity. No role, approval, custom claim, bucket ACL or public token
change. Existing swatch/drawing authorization remains on its established path.
See https://firebase.google.com/docs/rules/rules-behavior and
https://firebase.blog/posts/2022/09/announcing-cross-service-security-rules/.

One abandoned first octagon draft was initially left unpublished. Setup reruns now use a read-only
exact-code preflight rather than interpreting an asynchronous empty grid as absence.
Automatic approval review rejected archiving that production draft without specific
owner approval; the owner subsequently approved archiving it. OC archived only that draft, and
readback confirmed the intended three published products and the archived draft.
All original photo objects remain intact.
The three intended published products are distinct from that unused draft.
