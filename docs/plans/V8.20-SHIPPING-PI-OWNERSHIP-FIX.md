## Resulting behavior and ownership

ShipmentForm gives each PI import attempt an identity. Only the current mounted
attempt can apply parsed fields/lines, change the busy/error state, or accept an
ERP comparison. The chosen attempt's filename is shown while it is being read;
its file becomes the pending attachment only when its parsed data applies.

A failed replacement keeps the existing draft fields/lines and the last
successfully parsed PDF. Its message names the failed file and says it was not
attached. A failed first import preserves manual entry with no failed attachment.
Starting another attempt clears the previous ERP comparison and permanently
invalidates that attempt's late response, even if the replacement later fails.

ERP results carry the import identity and SO. Adoption checks both against the
current context and displayed SO. Editing or automatically allocating another SO
clears and invalidates the comparison synchronously. A Create submit during extraction
is blocked by the active-attempt ref as well as the existing disabled button.
Abandoned preprocessing/extraction/ERP completions cannot update another editor.

ShipmentPiUpload remains controlled presentation. It adds visible reading status,
wraps long filenames/error text and receives the attempted or committed filename
from the parent. The import remains available only for ordinary new orders;
saved orders, direct invoices and quote conversion do not gain an upload control.

Parsed-field precedence, selected-customer preservation, zero-line/manual review,
normal ERP adoption and nonblocking missing-ERP behavior retain their existing
contracts. No schema, endpoint, AI prompt, file-upload destination, saved-order
batch, stock, pricing/financial synchronization, number allocator or access policy
changes. The other health-review findings remain open and separately scoped.
