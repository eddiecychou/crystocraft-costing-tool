## Review and implementation plan

The existing Crystal editor combines customer-visible catalogue content, images
and actual variants. Private stock linkage already exists, but there was no
supplier-cost panel. Corporate Gifts has a supplier quote editor with three-decimal
unit/tier inputs, supplier-file reuse and attachment-only save safeguards. The
older Range quote editor lacks those safeguards. Crystal media deliberately uses
immutable Firebase files and authenticated reads; the Corporate image gallery's
token-URL/replacement model cannot simply be mounted here.

The bounded implementation:

1. Add a supply-gated **Supplier quotes & costing** panel to the Crystal editor.
   Select the exact size/colour variant and explicitly link an existing internal
   cost component. Quotations remain in its existing `supplier_quotes` tree.
2. Reuse the Corporate Gifts quote editor through a range-path adapter. Preserve
   supplier identities, precision, tiers, MOQ, combined tooling/sample charge,
   three lead times, notes, source files, preferred quote and normal denormalized
   preferred-cost behavior. Existing quotes never auto-extract replacement prices
   when files are attached. Missing MOQ/lead time remains unknown, not zero.
3. Keep associations on the supply-only `range_components` record, separate from
   the existing stock mapping. No fields are added to customer-readable
   `crystal_products`, variants, images, enquiry snapshots or catalogue exports.
   Existing supply rules protect the link, quote and source-file path; no rules,
   index or schema deployment is part of this implementation.
4. Show the same quotation from the supplier record with its Crystal variant
   identity. Supplier-to-Crystal editing requires both `swatch` and `supply`, just
   like the new route; existing generic Range access remains separately scoped.
5. Add batch image upload/retry, preview, original download, description editing,
   cover selection, archive/restore and crop/rotate as an explicit separate draft
   copy. Retain original bytes and publication safeguards. Image refresh must
   preserve unsaved catalogue text and the original product revision.

One internal cost component represents one actual catalogue variant; its quotes
all apply to that variant. Linking an already associated component elsewhere is
rejected. Multiple existing components linked to one variant are flagged for
review and are not silently summed or merged. New components use a stable
per-variant ID and the existing canonical code-reservation workflow; existing
code matches must be reviewed/reused, never duplicated.

## Further improvements from the module study — proposed only

1. **Clarify the OC page's three responsibilities.** Keep customer catalogue
   facts, actual variants, and internal costing visually distinct. Show compact
   per-variant readiness (photo/specification/confirmed quote/stock review), with
   truthful unknown states rather than a single misleading “complete” badge.
2. **Variant-aware photographs.** A later explicit photo-to-variant association
   could make sizes and colours easier to recognize. It needs a schema/privacy/
   publication plan; do not infer colour associations from image filenames or AI.
3. **Drawing-based project brief.** Preserve one Fabric experience and the existing
   enquiry flow. Consider a small drawing/application/quantity checklist and
   reviewed drawing revision internally; keep public pricing enquiry first.
4. **Separate supply policy from stock.** Show confirmed made-to-order capability
   versus reviewed on-hand clearance clearly. Keep original Swarovski provenance,
   condition and stock-only treatment distinct from Crystocraft alternatives.
5. **Broader quotation reliability.** The legacy generic Range editor still needs
   the Corporate attachment-only safeguards. Route/caller review should precede
   a wider migration. Source-file tokens are existing private-record references;
   never serialize them into customer data to make opening easier.

These proposals are not added to the current feature scope automatically. Keep
the existing market proposition: clear actual components, useful photographs,
customization enquiries, and human-confirmed pricing from drawings/application.
