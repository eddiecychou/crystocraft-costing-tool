# Buyer enquiry drafts on a shared browser

The customer portal stores the selected products, quantities and item notes separately for each signed-in Firebase user on that browser. Buyers at the same company have separate drafts. Signing out removes the mounted enquiry form and returning to the same account restores its saved lines. Removing an item or clearing a draft affects only its owner.

Older portal versions used one shared browser key with no owner ID. The new portal leaves that key untouched and never imports its contents. A buyer who only had an older, unassigned draft must reselect those items. Messages and file selections keep their previous behaviour as temporary form inputs. A change of identity during submission cannot assign an enquiry or its drawing to the new buyer. This release changes client code and requires no Firebase rules change or server data migration.

## Fictional verification

Two fictional buyers linked to the same fictional company used one Chrome tab with the real portal sign-in form and local Firebase Auth and Firestore emulators. Each started with an empty enquiry, selected a different product and added a distinct note and quantity (7 or 14). On the second sign-in each saw exactly their own line, quantity and note, including after refreshing. The ownerless legacy sample never appeared. The emulator contained zero submitted enquiries at the end.

The automated regression also switched directly between buyer identities, invoked a stale cart callback, and cleared one buyer’s draft. The other buyer’s draft survived. Run it with `node --test qa/enquiry-draft-privacy.test.mjs`. The same-browser rehearsal is in `qa/enquiry-draft-browser.mjs`.
