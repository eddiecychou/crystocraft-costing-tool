## Lessons and resumption checks

- Preserve behavior first; isolate confirmed corrections from presentation moves.
  Source parity alone does not establish async lifecycle or export correctness.
- Errors must not masquerade as empty data or successful writes. Keep fresh-source,
  identity, atomic-save, completeness and readback safeguards when adding helpers.
- Preserve unknown versus zero, stored money precision and approved accounting
  values; a display fallback is not authority to overwrite a financial record.
- Keep customer projections, internal costs, source attachments, stock ownership
  and independent sending identities separate. Test denied access, not just hidden UI.
- Use fictional write boundaries and existing QA identities. Never send customer
  emails, issue invoice numbers or alter stock as a smoke test.
- Each authorized release still requires both exact-SHA GitHub jobs before any
  deployment, then fresh candidate and production admin/customer plus feature
  checks under [RELEASE-WORKFLOW.md](../skills/RELEASE-WORKFLOW.md). Documentation
  alone does not authorize an application or Firebase rules deployment.
