# Range preferred supplier quote review

26 November 2026, Australia/Sydney. Reviewed the ordinary Crystocraft Range
component quote editor and preference control at `7189151b3b7d164701618cd335240138ce495b2d`.
All writes ran on a loopback Firestore emulator with two fictional Supply
staff accounts, fictional quotes, and the repository's existing rules.

## Findings and fictional results

The quote editor stores supplier quotes on child records. The component keeps a
copy of the preferred quote's unit price, currency, tiers, tooling and sample
charge, supplier display name and quote ID. Range Costing uses the component
copy for its estimates. The ordinary Range write path saves the quote or
updates preferred flags before separately refreshing that copy, so individual
writes can commit even if the operation reports an error.

## Proposed fix

1. **Commit each Range quote change and its costing together.** Move create,
   commercial edits, explicit selection, clearing and deletion into a
   transaction on the existing component. Read the parent first, list current
   quote references from the server and re-read the required quotes in the
   transaction. Update the parent in every operation that can affect
   preference or the costing copy so concurrent operations retry against
   current data. Commit the target quote, preferred flags and costing fields
   together. With two explicit selections, the last successful selection wins.
   Reject a selection of a deleted quote before clearing any flags. When the
   preferred quote is deleted or explicitly unselected, clear its active
   costing without promoting an unselected alternative. Reuse the Corporate
   Gifts transaction pattern and leave Crystal's product, variant and supplier
   checks in place.
   [Corporate Gifts transaction](../../src/corporateSupplierQuotes.js#L16) ·
   [Crystal variant transaction](../../src/criticalComponents.js#L186)
2. **Apply only the user's changes.** Reuse the Corporate Gifts field-patch
   pattern. Compare the touched terms with the original values and stop if a
   newer change conflicts with them. Preserve unrelated terms and files, and
   only change the preferred checkbox when the user changed it. Keep
   attachment-only saves on the current quote-only transaction. For a mixed
   edit that changes files, check the original attachment list inside the
   transaction before writing it. Keep existing quote IDs, supplier links,
   numeric precision and legacy quotes with no linked supplier.
   [Field patch pattern](../../src/corporateSupplierQuotes.js#L5) ·
   [Range supplier field](../../src/pages/RangeQuoteForm.jsx#L270)
3. **Keep failed drafts safe to retry.** Allocate a quote ID once per create
   draft and reuse it with the same submission identity. If confirmation is
   lost, verify that exact saved quote before treating the retry as complete.
   Retain successful uploads for that retry. Surface save, selection and
   deletion errors at the action and retain the draft on a conflict. A
   separately started quote should receive its own ID.
   [Range selection action](../../src/pages/RangeComponentForm.jsx#L39) ·
   [Range delete action](../../src/pages/RangeQuoteForm.jsx#L347)

This change belongs in the ordinary Range editor. Keep the buyer's stored
price, the Range pricing hold, existing permissions and the scoped B0016
setup workflow. Supplier merge also writes a quote's supplier identity and the
component's preferred supplier name. Cover that overlap with a fictional
regression before claiming consistency across both workflows. Preserve historic
records. If a component already has conflicting flags or a missing preferred
quote, identify it for review instead of inferring a supplier or bulk
rewriting pricing.

## Acceptance checks for implementation

- Repeat both two-editor timings. The resulting component quote ID, flag,
  unit cost, tiers, currencies and tooling fields agree.
- Deny a create, edit and delete at commit. Reload and confirm every quote
  and cost field still agrees with the pre-save state. Retry the same create
  and simulate losing the success response. Both return one quote ID and keep
  the same uploaded file. A deliberate second quote creates a distinct ID.
- Delete the selected quote and reload. The active costing clears, alternative
  quotes and their files survive, and a stale selection of the deleted quote
  has zero effects. Deleting an unselected quote preserves the selected cost.
- Save a PDF alone and a note alone while another editor changes the price,
  preferred selection or attachment list. Preserve the other editor's changes.
  Verify a conflicting edit to the same field retains the unsaved draft.
- Recheck legacy quotes, supplier links, Crystal variants, component stock,
  buyer prices and the B0016 hold using fictional records.

## Local implementation

- The ordinary Range writer now saves the target quote, preferred flags and
  the component's costing copy in one Firestore transaction. Transactions
  for the same component retry when another editor changes the preference.
  Clearing or deleting the selected quote clears the linked cost. If an
  older record has inconsistent preference flags, explicitly select the
  correct quote on the component before saving other commercial edits.
  [Range transaction](../../src/criticalComponents.js)
- Existing quote edits apply the fields changed in the form. A conflicting
  edit keeps the form and its attachments open. Price edits also check the
  currency they depend on. Deletion checks the quote loaded by the editor,
  including its attachments. Attachment-only saves remain quote-only and
  accept a retry if the exact attachment list is already saved.
  [Range quote editor](../../src/pages/RangeQuoteForm.jsx) ·
  [Attachment transaction](../../src/supplierQuoteAttachments.js)
- An open new-quote draft keeps a stable ID and reuses successful uploads.
  A fingerprint of the create payload lets a retry recover its exact saved
  quote without repeating the preference update. A different payload for an
  already saved draft stays open so the editor can reconcile the changes.
  Each separately started quote has its own ID.
  [Range quote editor](../../src/pages/RangeQuoteForm.jsx)

The transaction uses the existing Firestore rules and fields, plus an optional
fingerprint on new Range quotes. It requires no data migration. This is a
local implementation and verification record.
