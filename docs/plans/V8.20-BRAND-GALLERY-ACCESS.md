# Brand Gallery access and original file migration

The 19 November inventory matched 59 company gallery records to 59 Storage objects. All carried permanent Firebase download credentials. Fifty-three were customer-private, five internal and one a public reference. Public-reference status and marketing consent retain their separate meanings. The gallery original itself requires an approved company login or CRM staff access.

## Release sequence

1. Check fictional approved, pending, suspended, unlinked and other-company accounts, CRM access, revocation during an existing session, previews, original downloads and file visibility. Run both required GitHub jobs for the release commit.
2. Verify the candidate with fresh staff and buyer sign-ins. Confirm production rules match the previous tracked rules before publishing the reviewed changes. New uploads use a create-only GCS session with original bytes and a private cache policy. The media endpoint authenticates through Firestore on each request, including byte ranges.
3. Run `scripts/migrate-brand-gallery.mjs` with a short-lived operator credential on stdin and OC’s bucket in the environment. Review the counts and original fingerprint. After the application cutover, repeat with `--apply=<reviewed fingerprint>`. The script replaces only the descriptor link, checks the document update time, removes the old object download token with generation and metadata preconditions, and sets private caching. A mismatch stops the operation for review. A retry resumes from the current metadata.
4. Read the inventory again. Require the same object generations, sizes and checksums, zero tokenized originals and zero legacy descriptors. Use the protected application for rollback or recovery. Keep old credentials revoked and retain the private storage policy during any app rollback. Previously downloaded copies cannot be recalled.

Brand Gallery uploads live under `customer-assets/`. Product photos independently published in the storefront retain their catalogue publication settings. Internal customer documents use their separate private file service.
