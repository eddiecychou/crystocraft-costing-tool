## Changes and preserved boundaries

- ShipmentForm validates save-time accounting amounts against the current
  computed total, passing an override to validation without changing header's
  recorded Woo checkout total. Woo allocation still uses the saved amount;
  unknown-total/payout guards and stored-record audit validation remain intact.
  Real accounting differences still require a reason. Deposit validation,
  line precision, currency, calculations and write sequencing remain.
- Validation/write errors now also appear as a role=alert message immediately
  beside submit actions in edit, ordinary-create, direct-invoice and quote-prefill
  modes. Import feedback remains at the dropzone. Failures retain unsaved values
  and permit explicit retry. Existing timed-write semantics are unchanged; this
  is not a transaction redesign or proof of every late server rejection.
- CustomerDetail retains its public export/route but keys an internal page by
  customer ID. Customer-scoped UI/subscriptions reset together on navigation.
  Same-customer renders retain unsaved state. The initial loader ignores
  abandoned results, handles absent customers and rejected reads, and offers
  safe error/Retry. No role/module/query/write target changes.
- CustomerCollapsible keys an internal section by the existing storageKey,
  immediately reading that customer's saved preference. Existing session keys,
  defaults, markup, spacing and toggle behavior remain.

Only three application files change: ShipmentForm.jsx, CustomerDetail.jsx and
components/crm/CustomerCollapsible.jsx. No backend, rules/index, schema, rates,
number allocation, stock/PO, send-policy or export-template changes. Already
started user-authorized operations are not cancelled by this correction.
