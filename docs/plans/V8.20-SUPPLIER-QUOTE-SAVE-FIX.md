# V8.20 supplier quote save conflict — 29 October 2026

Implemented and locally verified; application release is pending the required
exact-SHA GitHub checks, candidate/production role gates and release authorization.

## Problem and change

The owner's BIHONG quote remained on Edit Supplier Quote after Save Changes.
The open production form exposed the error "Attachments changed in another
session. Reopen this quote before saving" above the form, outside the supplied
screenshot. Source inspection and an isolated execution of the actual transaction
callback reproduced that exact error with identical attachment values whose map
keys were reordered. A real concurrent attachment change is also a legitimate
reason for this warning; the original tab's hidden cached baseline was not read.

Quote form, tier and attachment comparisons now compare values recursively,
ignoring map key order while preserving field presence, types, array order,
timestamps and every attachment detail. The existing SEO-review comparator was
moved unchanged to `src/firestoreValue.js`; its existing export is retained.
The attachment-only transaction still writes only attachments, preserving
concurrent approved prices, MOQ, tooling, notes and supplier preference. Real
attachment conflicts remain blocked. Save errors now appear and receive focus
immediately before the save/cancel/delete actions, retaining entered values.

No migration, duplicate quote, replacement PDF, pricing recalculation, AI
extraction, rules change or live-record edit is needed for this fix.
