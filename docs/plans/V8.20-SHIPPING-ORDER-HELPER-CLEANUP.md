# Shipping order helper cleanup

Removed `createOrderWithLines` and `createOrderWithLinesAllocatingSo` from `src/shipping.js`, along with the SO allocation imports used only by those helpers. The source audit found no executable callers. Manual, PI and duplicate creation use saved order requests, quote conversion uses its own recovery endpoint, and Woo uses `createOrderWithLinesAtId`.

## Fictional verification

- 11 Firestore and Storage cases covered manual and PI order creation, acknowledgement loss, recovery, and intentional repeats. Retries recovered the original order, lines and SO. Separate requests could create separate orders.
- 29 Firestore cases covered Quote → Order recovery, concurrent requests and intentional additional partial orders with separate customer POs.
- 6 Firestore and real-page Woo cases covered successful creation, retry without duplicate writes, overlapping imports, and **Needs review** for surviving lines, invoices and UC Registry matches. Failed ledger reads left the order and line collections untouched until verification was retried successfully.
- 46 additional unit, UI and fictional PostgreSQL cases covered the order request, quote conversion and Woo gateway contracts. The required GitHub emulator job also ran the Duplicate Order and Direct Invoice suites.
