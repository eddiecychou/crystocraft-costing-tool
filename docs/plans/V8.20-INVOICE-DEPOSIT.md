# V8.20 — optional sales-invoice deposit — 30 October 2026

Status: released and production verified. Both exact-SHA GitHub jobs and fresh
admin/customer checks on candidate and production PASS. No production invoice,
payment, stock, UC registry entry or security rule has been edited. Normal QA
sign-ins may record login stamps.

The shared order/invoice editor now has an optional **Deposit paid** amount in
the order currency beneath Accounting Total. A positive deposit shows **Total
outstanding** immediately. Blank/zero leaves the outstanding row hidden; the
editable field stays available so a deposit can be entered later. The field is
saved as `orders.deposit_paid` (number/null), included in the canonical order
normalizer and both create/edit paths, and reloads/clears correctly.

The balance is the accounting invoice value, when set, otherwise the calculated
line/discount/charges total, less deposit paid. Currency-cent rounding applies
only to the derived balance. Example: USD 7,613.94 less USD 2,000 = USD 5,613.94.
Full payment shows zero outstanding. Malformed, negative and above-total values
are rejected, including by the shared save validator.

A deposit is a payment against an invoice, so it does not reduce sales value,
discounts, `total_amount`, `accounting_total` or the PBIS/upsert-invoice amount.
This is a manually recorded invoice deposit, not an automatic cash receipt or
UC-ledger posting. Existing duplication uses a header whitelist and does not
carry the source invoice's payment into a new order.

Admin and customer sales-invoice print views and real Excel downloads include
the deposit deduction and total outstanding only for a positive deposit. Amount
in words then describes the outstanding amount. Existing invoices without a
deposit retain their previous output; proforma totals/output stay unchanged.
Customer ownership checks and the legacy ERP invoice path are unchanged.
