# Saved Shipping requests that need review

Saved manual and PI requests now show **Needs review** when their linked
order is missing or its creation timestamp differs from the one recorded
on the request. The list links to the request detail, which explains what
happened and offers a separate-order link. An explicit separate order still
requires Create. The original request cannot reopen or resume the old order.

The server derives this state on each read, including paginated list reads.
Status and prepare replay return the review state. Commit replay rejects
the request before allocating an SO or writing the order or its lines.
The existing receipt and any original PI are retained.

Fictional Firestore and Storage tests covered a removed order and a
replacement at the same ID for each of the manual and PI paths. Concurrent
status, prepare replay, commit replay and list reads left the order count,
SO counter, receipt, lines, and original PI generation unchanged. Pagination
kept the review row on its expected page. Chrome verified the list and
detail labels and their behavior after reload.
