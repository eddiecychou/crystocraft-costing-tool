# Packing scenario edits and Freight history

14 November 2026 AEDT · Review of `f05bb06e` using fictional orders

## Observed behavior

| Case | Result after reopening or reading back from Firestore |
| --- | --- |
| Edit a plan after choosing a quote | Packing went from two cartons, 0.27 CBM and 28 kg chargeable to three cartons, 0.62 CBM and 51 kg. The full quote and decision documents stayed identical, including the original cargo, USD 145.25 price, saved HKD equivalent and charge breakdown. The comparison showed the revised plan title over the old quote without a warning, making the price appear to apply to the new plan. |
| Save an edit while a stale quote submission is in flight | When the edit changed the totals and committed first, the quote was rejected. When the edit changed the saved contents and revision while leaving the three comparison totals equal, the stale quote succeeded. |
| Delete a scenario while a stale quote submission is in flight | When deletion committed first, the stale quote was rejected and no quote document appeared. |
| Save and choose a quote while a scenario deletion is in flight | When the quote and its choice committed first, the other tab still deleted the Packing header, carton and contents. The full quote and decision survived. The quote card showed the original scenario as unavailable and kept the chosen marker. The comparison table omitted the price. |
| Delete an unused scenario | The delete succeeded and produced no quote. |
| Competing Packing saves | Two saves from the same baseline left one complete winning revision. The other save received a conflict. |
| Save a Packing edit and delete from another tab | When the edit committed first, the stale deletion failed and the revised carton contents survived. When the deletion committed first, the stale edit failed and did not recreate the plan or its children. The existing rejection may surface as a Firestore rules error. |

The quote transaction currently reads the scenario and compares its carton count, CBM and chargeable weight. Packing save and delete compare `packing_save_id`. The quote transaction does not change any document that Packing deletion checks, which explains the quote-first outcome. The comparison table builds columns from current scenarios and explicitly unlinked quotes. A quote that still names a deleted scenario therefore has no comparison cell. ## Proposed behavior

1. **Protect Packing scenarios with saved Freight quotes.** Keep permanent deletion available for unused plans. Block it for a plan referenced by any saved quote, including an unchosen one. Offer Archive for a referenced plan if operators need it off their active list. Preserve the original scenario ID, contents, print access and quote links. Archive should leave the quote's price, cargo and choice intact. Archived scenarios should stay readable from earlier quotes and be excluded from new quote pickers.
2. **Compare the revision used to quote.** Save the scenario ID, the observed Packing save revision and the saved label on new Freight quotes. Check that same revision at creation, even when the three totals are equal. Reuse the existing retry ID and keep the user's draft price and notes on a conflict. Require a fresh review of the cargo before saving against a changed plan, including any manually entered cargo values. Existing quotes without a reliable revision keep their recorded data and may show that the quoted revision is unknown.
3. **Keep quoted and current cargo visible.** Allow authorized Packing edits. Display the quote's original cargo, original price and currency, stored HKD comparison and charge breakdown. Show when the current scenario revision differs. Give revised, archived or unavailable source plans a historical comparison entry so quotes remain visible without competing as the cheapest option for current cargo. Keep an already chosen quote visible and chosen until an operator explicitly changes the Freight decision. A renamed plan or changed Packing star must not change that decision.
4. **Enforce the dependency at commit.** Quote creation and permanent scenario deletion need a common transaction guard. One design is to move those two operations behind the existing Shipping permission on the server and have both transact against the scenario and its references. Verify in the emulator that the create/delete race cannot commit both. Check legacy references before allowing deletion. Block direct writes that bypass the guarded paths when the release introduces them. An archive action should share the same boundary so concurrent creates see the correct archived state. Keep rollout and any supporting index or migration explicit. [Firestore transaction isolation](https://firebase.google.com/docs/firestore/transaction-data-contention)

## Acceptance for a later change

- With fictional linked, unlinked, selected and unused scenarios, assert exact quote IDs, monetary amounts, price breakdown, FX comparison, cargo, choice and carton/contents readback.
- Run both commit orders for quote versus delete and Packing save versus delete. Include a same-totals edit, a stale tab, two saved quotes on one scenario, a lost acknowledgment and a retry. Verify losing drafts remain available for review. A lost quote response must recover the same committed quote.
- Check full comparison visibility and the historical indication after edit, archive or a pre-existing missing scenario. Verify unused-plan deletion, existing print access and Shipping staff permissions. Verify approved customer and unauthenticated callers cannot read or change the internal records.
- Preserve old links and explicitly unlinked quotes. A later historical repair requires source evidence and owner approval.

## Implemented guard

The Shipping API now checks the scenario revision the operator saw. A linked
quote writes a counter on the same scenario that permanent deletion checks.
Deletion checks for any saved reference, then removes the unused scenario,
cartons and contents in one transaction. Firestore rules require Packing
content edits to publish a fresh revision in the same write. A rejected quote
keeps the draft price and notes and offers to reload the cargo for review.

The Freight comparison keeps older quotes visible with their original cargo
and prices. A prior, unknown or unavailable revision has its own comparison
column and is excluded from the current-cargo ranking. Freight choice changes
only through the operator's existing Choose and Unmark actions. Archive
remains a separate proposal. The release needs the app and Firestore rules.
Existing quotes, links and decisions require no data migration. The Hui Jia
quote remains unlinked, and the freight charge remains pending source evidence.

The final local run passed 36 Shipping emulator cases, five two-tab Chrome
cases with fictional orders, 112 access-rule checks and 31 Packing and PO
checks. Browser cases used the live form and comparison UI, with Packing
mutations through the same persistence functions as the editor.
