## Business values and bounded fix

The original owner/Cindy mapping is in PROJECT-PLAN.md, V8.9 section 7 and V8.10:
Woo orders are paid in full at checkout. UC Registry total/deposit use the saved
order total, balance is zero, and payout date is the recorded settlement date.
Non-HKD remarks show gateway fee in transaction currency and recorded net payout
in HKD; HKD transactions omit this note. No conversion or inferred bank amount.
The invoice's separate editable deposit_paid field is not auto-filled.

normOrder discarded woo_net_payout_hkd, including when normalizing new imports;
the form-header load discarded total_amount. The normalizer now retains the
payout via the existing numeric-or-null helper; the page carries the saved
checkout total with a null default. Neither value is rounded or recalculated.

A safety guard skips registry fill if that total is unknown: the existing
registry endpoint converts null numbers to zero. Allocation and immediate saved
invoice-number persistence still complete, with the usual warning that automatic
registry amounts were not overwritten. Known zero remains valid. The recorded
checkout amount is used, not a different paid amount derived from unsaved line
edits. Missing HKD settlement keeps the manual fallback; transaction-currency
net is never substituted. Existing manual notes remain unchanged.

Application diff: seven added lines in ShipmentForm.jsx and shipping.js. All
other 507 existing app/server/rule files match baseline
43073fc757134510065dcc969c7f2c1e64c3041b. No allocator, service/backend, SQL/RPC,
schema, rules/auth, UI markup/style, rates, number-series or calculation changes.
No historical mutations. Manual invoice deposit/outstanding and non-Woo channels
remain. Source proof is in ignored qa/out/woo-invoice-data/source-scope.json.
